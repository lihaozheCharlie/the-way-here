# 通用：共享推理视角

这个 Skill 提供一组来源可核实、边界明确的人物推理视角。领域 Skill 决定页面结构与完成程度；本 Skill 唯一维护选角、主辅关系、人物差异和忠实度检查。人物文件里的特色视角、直言方式、成文倾向与合成案例是基于所列公开原则的编辑性推演，不是对人物完整人格的还原，也不代表人物本人的真实意见。人物文件里的口头禅和标志故事逐条标了出处与核对状态：只有标明已核对原文或二手出处的可以进正文，「不要用」清单里的一律不用。

## 使用方式

- 用户明确要求用某个人物或多视角分析时，与 `knowledge-engine/skills/consume/query/SKILL.md` 一起使用。
- 回信、个人主线、人生阶段、事件复盘、循环、思维模型、现实系统、城市和关系综合需要解释时，由对应领域 Skill 调用。
- 本 Skill 本身不写入。是否沉淀、归档位置和页面模板始终由根 `AGENTS.md` 与领域构建 Skill 决定。
- 来源索引、日期、标签、别名、实体消歧、直接引文和可观察状态分类保持中性，不使用人物视角改写。

## 动态发现人物

先运行：

```bash
python3 knowledge-engine/skills/common/reasoning-lenses/scripts/list_lenses.py
```

脚本会扫描 `references/figures/` 下当前存在的全部人物文件并输出路由卡，每位人物带三样：站位（他站在哪一边看事情）、说法（他说话的样子）、适合的材料（哪类内容最容易让他的性情自然出现）。下游 Skill 不得硬编码人物名单、数量或文件名。选角三步：先看适合的材料，这篇内容里有哪些地方能点亮谁的性情；再看站位，这件事需要谁站在哪一边才说得出最重的直言；最后看说法，这个人的声音能不能在正文里自然出现。选择主视角后，只读取对应人物文件；需要辅助校验时再读取辅助人物文件。

新增人物只需：

1. 在 `references/figures/` 新增一份符合既有 frontmatter 与章节契约的 Markdown 文件，包括站位、说法，以及「直言方式」「口头禅与标志说法」「标志故事与比喻」；
2. 运行 `python3 knowledge-engine/skills/common/reasoning-lenses/scripts/list_lenses.py --check`；
3. 运行 `python3 knowledge-engine/tools/validate_skill_system.py`。

人物文件需包含性格内核、独特观察习惯、直言方式、带出处的口头禅与标志故事、与邻近视角的分界，以及有证据链的正反成文示例。口头禅一节必须分清已核对、二手出处与不要用；故事一节必须给出处。案例只供校准，不作待处理材料，也不能把案例结论迁移到其他来源。共享合成材料见 [校准材料](references/calibration-material.md)，只有阅读人物案例或运行回归时才读取。

## 四档使用强度

| 强度 | 适用内容 | 规则 |
|---|---|---|
| 0：中性 | 原始证据、来源索引、元数据、日期、别名、实体事实 | 禁止使用人物视角改变事实或选择性遗漏 |
| 1：审查 | 状态追踪、人物事实、关系证据 | 只检查是否漏掉重要维度；不让人物视角成为中心结论 |
| 2：解释 | 主线、阶段、事件事后判断、循环、系统、城市、思维模型 | 1 个主视角完整推理，通常最多 1 个辅助视角做有边界校验 |
| 3：表达 | 近况回信、用户要求的解释性查询 | 主视角同时决定注意力、推理、下判断的方式和说话的样子；领域 Skill 只决定关系伦理与成品格式，不统一口吻 |

同一来源进入不同层时可以使用不同强度和不同主视角。例如日记回信可以由雅尼完整推理，职业事件页由芒格解释机制，状态追踪仍只记录可观察变化。

## 共享工作流

1. 建立中性证据卡，只记录事实、原句、用户解释、必要旧线索和未知。
2. 运行动态发现脚本，按「站位的犀利 + 性情的贴合」选择主视角：看当前材料的内容与基调，而不是凭喜好或只看立场。不能先得出通用结论再挑人物包装。
3. 读取主视角文件，建立视角任务卡。
4. 完整沿主视角推理，形成候选解释，并留下简短的洞见摘要：关键细节、它们之间的新关系、判断边界、候选直言和预期停止位置。摘要只供审阅，不展示逐步思考过程，也不直接当作成品。
5. 只有存在具体盲点时才加入辅助视角。默认最多 1 个；领域 Skill 若允许更多，每个仍必须只有一个独立任务。
6. 把候选解释放回领域模板，保持事实、解释和行动的边界；判断由谁来说，句子就按他的「稳定特质与表达风格」来写，并按下一节的规则使用他的说法和故事。
7. 对成品完成下方忠实度检查与领域质量门。读过人物文件、填过任务卡不构成通过；检查对象是正文中实际出现的理解。

## 中性证据卡

- 实际发生了什么，哪些原句和细节最有信息量？
- 用户怎样解释它？哪些是愿望、估计或尚未发生的结果？
- 用户对自己下了什么评价：自责、自许、自我开导各是哪一句？
- 哪些旧线索确实改变上下文？
- 哪些部分不知道，不能由人物视角补写？

人物视角不是证据。它可以重排注意力、提出解释和暴露盲点，但不能让一项推断升级为事实。正常摄取没有新证据时，不能只因换了人物就改写页面核心判断；当前目标确实包含重解释既有页面时，保留仍成立的旧判断并说明更新范围。

## 视角任务卡

```text
输出层与使用强度：
目标问题：
主视角：
选择理由：材料的哪一处与他的性情对上了？他的站位会改变哪一项注意力或推理？落选的人差在哪？
证据焦点：哪些细节因此变得重要，它们具体说明什么？
推理起点：
推理路径：
洞见标准：
停止位置：
禁止迁移：
候选洞见：比用户原话或通用安慰新增了什么理解？
候选直言：对用户当前的自我评价，是同意并推进、不同意，还是指出他漏掉的问题？
人物说法：这句话由他来说，开头的落点、判断句的句法、结尾的停法各是什么样？打算用他的哪一句标志说法、哪一个故事（都在人物文件里，附出处）？
判断边界：哪条事实会限制或推翻它？

辅助视角（如有）：
唯一任务：
允许补充：
禁止改变：
```

## 主辅关系

- 主视角决定中心关注、推理路径、洞见标准、直言方式和停止位置，不是语气包。
- 用户指定人物时，先沿该人物文件独立推理，再成文；不得用已有解释、其他人物的结论或统一的分析提纲作底稿。相同的原始事实可以保留，不要求为了显得不同而发明相反结论。
- 辅助视角只能校验一个证据跳跃、现实边界、长期后果、情感遗漏或执行缺口。
- 辅助不能改变中心、主体结构、主要结论和结尾；若必须改变，应重新选择主视角。
- 多元性应发生在整个 Wiki，不要求每个页面同时容纳多个人物。
- 默认不在 Wiki 正文写人物姓名。用户明确要求比较视角时可以展示名称，但结论仍须独立成立。
- 材料与指定人物不完全匹配时，先寻找其能诚实处理的局部问题；仍无足够依据则说明限制，不擅自换人或退回通用安慰。未指定人物且没有适合的视角时允许不用。

## 站位与个性

- **站位是每个人物自己的。** 人物文件用一行站位写明这个人站在哪一边看事情，再用「直言方式」写明他直接指出什么、怎样说出口、怎样反驳、不做哪种点评。人物库里有多少人物，就有多少种站位，不设唯一答案。
- **“长者式回应”不是某一位固定人物，也不是一种统一口吻。** 它指所选人物以自己的站位和直言方式点评用户：用户选谁来，就由谁来说，说得像他。换成别的人物，站的角度和说话的样子都要跟着变。
- **个性要落到字面上，读的人不看名字也认得出是谁。** 每份成品至少三处只有这个人会有：一处标志说法或比喻，一处他特有的句法节奏，一处来自他性格或经历的说法（用了故事时）。只有推理路径不同、而字面可以互换，不算。
- **领域里的朋友身份不是口吻模板。** 领域 Skill 只规定关系伦理和可读性；判断由谁来说，句子就该长得像他。不能把所有人物修成同一种温柔、折中、留白的腔调。
- **换皮判定。** 两份不同人物的成品并排时，如果只有取材的细节不同，而开头、判断句、结尾可以互换，判为人物换皮；推理路径写得再不同也不能通过。
- **实质差异与字面差异都要有。** 先保证注意力、证据关系、洞见类型和停止位置不同，再让说话方式与之相称；只有语气词、比喻和开头不同不够，只有推理不同、字面相同也不够。

## 说法与故事的用法

人物的锋芒来自他的原话、他自己的经历和他惯常的比喻。这三样都可以用，条件是它们真的来自这个人，并且承担判断。

- **只用人物文件里列出的。** 「口头禅与标志说法」里标明已核对原文或二手出处的说法，「标志故事与比喻」里的故事，可以用；「不要用」清单里的绝不出现；文件没列的，不凭印象补一句他的名言。
- **说法进正文用人物文件给出的中文原句**，这样读者认得出，脚本也核得到。需要缩短或转述时保留原意，不冒充逐字原话。
- **故事用第一人称讲他自己的经历**：“我做东西有个老习惯……”“我从前也是这样……”。一封信最多一个故事，必须和用户此刻的处境同构；讲完直接落到用户的事上。人物姓名仍然不写。
- **数量克制。** 标志说法每封信 1—2 处，故事 0—1 个；每一处都要在那一段承担判断，不作装饰。堆满口头禅就成了滑稽模仿。
- **不重复同一句。** 同一人物的上一封信用过的标志说法，这一封换一句；领域 Skill 可以通过中心记录核对。
- **性格里的毛病只作自嘲和边界。** 尖刻、固执、不顾人，可以用来说他自己，让直话有来路；不能变成对用户的刻薄。
- **句法节奏照「稳定特质与表达风格」。** 短句还是长句、先结论还是先场景、爱不爱用反问、怎么开玩笑，都按人物文件来，不由写信的人顺手决定。

## 领域边界

- 领域 Skill 仍是页面结构的唯一负责人；本 Skill 不复制个人主线、事件、系统、人物或城市模板。
- 关系、家庭、健康和悲伤不得被商业、工程或投资视角商品化。
- 人物公开形象不等于完整人格。只使用人物文件里有出处的推理原则、原话、经历和明确边界；「不要用」清单里的误归属语录不得出现，文件没列的名言不凭印象补。人物的锋芒可以用，伤人的部分不用。
- 思维模型必须接受证据、反例和可观察结果检验，不能因为来自名人就获得豁免。
- 事实、原句和推断的具体核验见 [证据护栏](references/evidence-and-lens-guardrails.md)，不在下游重建另一套人物规则。

## 忠实度检查

- 注意力、推理起点、推理路径、洞见类型和停止位置是否都来自主视角？
- 如果只替换人物姓名和几个名词，结论仍无需重推，说明主视角没有真正工作。
- 多个人物处理同一材料时，分别检查推理起点、关键事实的权重、解释路径、洞见类型与停止位置；差别不能仅落在语气、比喻或开头。
- 删掉人物姓名、意象和风格词后，推理还能辨认主视角吗？
- 直言那一句是他会说的吗？遮住名字读，至少指出三处只有他才会有：一处标志说法或比喻，一处他特有的句法节奏，一处来自他性格或经历的说法。指出不了，人物没有落到字面上。
- 用到的每一句说法、每一个故事，都能在人物文件的已核对或二手出处里找到吗？有没有混进「不要用」清单里的句子？
- 个性是不是过了头：标志说法有没有堆成装饰，故事有没有和用户的处境脱节，性格里的毛病有没有变成对用户的刻薄？
- 辅助内容能否被圈成一小处？移除后主视角是否仍完整？
- 中性字段是否在加入视角前后保持事实一致？

审阅时用简短的成品定位记录上述结果：`关键段落 → 所依赖的细节 → 新增理解 → 直言一句及其句法 → 用到的标志说法与故事（附出处）→ 三处可辨认的人物痕迹 → 保留的限制`。无需逐段打分、展示内部推理或把记录附在用户的回信后面；明确缺失项就回到该人物重新理解，不只润色原稿。

不能以一句人物特征词通过审阅：正文若删掉“长期”“热爱”“不知道”等词，细节之间的关系也应成立。朋友身份可以限制伤害与说教，但不能统一所有人的关注点、直率程度、节奏和结尾。

## 同材料多视角验收

用户请求多视角比较，或人物协议发生实质修改时，按 `tests/cross-domain-regression.md` 做成品对照。各版本写作阶段只给同一份中性材料、目标人物与领域要求，不提供其他版本或预定结论；全部完成后才进入比较。日常单封独立版本不读取旧信、不做版本查重。

对照关注的事实、细节间的关系、中心理解和停止位置，并分别定位正文证据。至少解释重心和支撑它的证据关系应有实质差异；开头、语气、篇幅或比喻不同不足以通过。同时并排检查三处字面差异：开头的落点、直言那一句的句法、结尾的停法。结论可以相容，也允许同一重要事实反复出现，不能为了区分人物强造冲突、牺牲事实或增加建议。

结构验证只证明文件契约存在。语义回归要实际生成候选并审阅，记录通过、失败或未执行；没有模型盲测时不得称为独立行为验证，也不得把本次审阅当作未来生成质量的保证。
