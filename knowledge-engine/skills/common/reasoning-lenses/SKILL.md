# 通用：共享推理视角

这个 Skill 提供一组来源可核实、边界明确的人物推理视角。领域 Skill 决定页面结构与完成程度；本 Skill 唯一维护选角、主辅关系、人物差异和忠实度检查。人物文件中的特色视角、成文倾向与合成案例是基于所列公开原则的编辑性推演，不是对人物完整人格的还原，也不代表人物本人的真实意见。

## 使用方式

- 用户明确要求用某个人物或多视角分析时，与 `knowledge-engine/skills/consume/query/SKILL.md` 一起使用。
- 回信、个人主线、人生阶段、事件复盘、循环、思维模型、现实系统、城市和关系综合需要解释时，由对应领域 Skill 调用。
- 本 Skill 本身不写入。是否沉淀、归档位置和页面模板始终由根 `AGENTS.md` 与领域构建 Skill 决定。
- 来源索引、日期、标签、别名、实体消歧、直接引文和可观察状态分类保持中性，不使用人物视角改写。

## 动态发现人物

先运行：

```bash
python3 knowledge-engine/skills/common/reasoning-lenses/scripts/list_lenses.py
```

脚本会扫描 `references/figures/` 下当前存在的全部人物文件并输出路由卡。下游 Skill 不得硬编码人物名单、数量或文件名。选择主视角后，只读取对应人物文件；需要辅助校验时再读取辅助人物文件。

新增人物只需：

1. 在 `references/figures/` 新增一份符合既有 frontmatter 与章节契约的 Markdown 文件；
2. 运行 `python3 knowledge-engine/skills/common/reasoning-lenses/scripts/list_lenses.py --check`；
3. 运行 `python3 knowledge-engine/tools/validate_skill_system.py`。

人物文件需包含独特观察习惯、与邻近视角的分界，以及有证据链的正反成文示例。案例只供校准，不作待处理材料，也不能把案例结论迁移到其他来源。共享合成材料见 [校准材料](references/calibration-material.md)，只有阅读人物案例或运行回归时才读取。

## 四档使用强度

| 强度 | 适用内容 | 规则 |
|---|---|---|
| 0：中性 | 原始证据、来源索引、元数据、日期、别名、实体事实 | 禁止使用人物视角改变事实或选择性遗漏 |
| 1：审查 | 状态追踪、人物事实、关系证据 | 只检查是否漏掉重要维度；不让人物视角成为中心结论 |
| 2：解释 | 主线、阶段、事件事后判断、循环、系统、城市、思维模型 | 1 个主视角完整推理，通常最多 1 个辅助视角做有边界校验 |
| 3：表达 | 近况回信、用户要求的解释性查询 | 主视角同时决定注意力、推理和自然表达倾向；领域 Skill 决定口吻与成品格式 |

同一来源进入不同层时可以使用不同强度和不同主视角。例如日记回信可以由雅尼完整推理，职业事件页由芒格解释机制，状态追踪仍只记录可观察变化。

## 共享工作流

1. 建立中性证据卡，只记录事实、原句、用户解释、必要旧线索和未知。
2. 运行动态发现脚本，根据当前问题而非喜好选择主视角。不能先得出通用结论再挑人物包装。
3. 读取主视角文件，建立视角任务卡。
4. 完整沿主视角推理，形成候选解释，并留下简短的洞见摘要：关键细节、它们之间的新关系、判断边界和预期停止位置。摘要只供审阅，不展示逐步思考过程，也不直接当作成品。
5. 只有存在具体盲点时才加入辅助视角。默认最多 1 个；领域 Skill 若允许更多，每个仍必须只有一个独立任务。
6. 把候选解释放回领域模板，保持事实、解释和行动的边界。
7. 对成品完成下方忠实度检查与领域质量门。读过人物文件、填过任务卡不构成通过；检查对象是正文中实际出现的理解。

## 中性证据卡

- 实际发生了什么，哪些原句和细节最有信息量？
- 用户怎样解释它？哪些是愿望、估计或尚未发生的结果？
- 哪些旧线索确实改变上下文？
- 哪些部分不知道，不能由人物视角补写？

人物视角不是证据。它可以重排注意力、提出解释和暴露盲点，但不能让一项推断升级为事实。正常摄取没有新证据时，不能只因换了人物就改写页面核心判断；当前目标确实包含重解释既有页面时，保留仍成立的旧判断并说明更新范围。

## 主辅关系

- 主视角决定中心关注、推理路径、洞见标准和停止位置，不是语气包。
- 用户指定人物时，先沿该人物文件独立推理，再成文；不得用已有解释、其他人物的结论或统一的分析提纲作底稿。相同的原始事实可以保留，不要求为了显得不同而发明相反结论。
- 辅助视角只能校验一个证据跳跃、现实边界、长期后果、情感遗漏或执行缺口。
- 辅助不能改变中心、主体结构、主要结论和结尾；若必须改变，应重新选择主视角。
- 多元性应发生在整个 Wiki，不要求每个页面同时容纳多个人物。
- 默认不在 Wiki 正文写人物姓名和名言。用户明确要求比较视角时可以展示名称，但结论仍须独立成立。
- 材料与指定人物不完全匹配时，先寻找其能诚实处理的局部问题；仍无足够依据则说明限制，不擅自换人或退回通用安慰。未指定人物且没有适合的视角时允许不用。

## 领域边界

- 领域 Skill 仍是页面结构的唯一负责人；本 Skill 不复制个人主线、事件、系统、人物或城市模板。
- 关系、家庭、健康和悲伤不得被商业、工程或投资视角商品化。
- 人物公开形象不等于完整人格。只使用参考文件中有来源的推理原则和明确边界，不模仿口头禅、传奇形象和未经核实的名言。
- 思维模型必须接受证据、反例和可观察结果检验，不能因为来自名人就获得豁免。
- 事实、原句和推断的具体核验见 [证据护栏](references/evidence-and-lens-guardrails.md)，不在下游重建另一套人物规则。

## 忠实度检查

- 注意力、推理起点、推理路径、洞见类型和停止位置是否都来自主视角？
- 如果只替换人物姓名和几个名词，结论仍无需重推，说明主视角没有真正工作。
- 多个人物处理同一材料时，分别检查推理起点、关键事实的权重、解释路径、洞见类型与停止位置；差别不能仅落在语气、比喻或开头。
- 删掉人物姓名、意象和风格词后，推理还能辨认主视角吗？
- 辅助内容能否被圈成一小处？移除后主视角是否仍完整？
- 中性字段是否在加入视角前后保持事实一致？

审阅时用简短的成品定位记录上述结果：`关键段落 → 所依赖的细节 → 新增理解 → 对应人物判断习惯 → 保留的限制`。无需逐段打分、展示内部推理或把记录附在用户的回信后面；明确缺失项就回到该人物重新理解，不只润色原稿。

不能以一句人物特征词通过审阅：正文若删掉“长期”“热爱”“不知道”等词，细节之间的关系也应成立。朋友身份可以限制伤害与说教，但不能统一所有人的关注点、直率程度、节奏和结尾。

## 同材料多视角验收

用户请求多视角比较，或人物协议发生实质修改时，按 `tests/cross-domain-regression.md` 做成品对照。各版本写作阶段只给同一份中性材料、目标人物与领域要求，不提供其他版本或预定结论；全部完成后才进入比较。日常单封独立版本不读取旧信、不做版本查重。

对照关注的事实、细节间的关系、中心理解和停止位置，并分别定位正文证据。至少解释重心和支撑它的证据关系应有实质差异；开头、语气、篇幅或比喻不同不足以通过。结论可以相容，也允许同一重要事实反复出现，不能为了区分人物强造冲突、牺牲事实或增加建议。

结构验证只证明文件契约存在。语义回归要实际生成候选并审阅，记录通过、失败或未执行；没有模型盲测时不得称为独立行为验证，也不得把本次审阅当作未来生成质量的保证。
