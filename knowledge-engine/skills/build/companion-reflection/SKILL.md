# 构建：近况回信

检索相关旧线索时依赖 [common-retrieval](../../common/retrieval/SKILL.md)，只扩展能实质改变本次理解的来源；本文保留中性证据卡、人物视角与朋友式回信流程，不套用预测检索预算。

## 分工

回信由四层组成。每件事只在其中一层定义，其余地方只引用，不复述。

| 层 | 在哪里 | 只负责 |
|---|---|---|
| 人物 | 共享人物库里每人一份 | 他站在哪一边、怎样想、他的原话和经历、说话的样子、在哪里停 |
| 共享协议 | `knowledge-engine/skills/common/reasoning-lenses/SKILL.md` | 选角、主辅关系、忠实度、个性是否落到字面 |
| 回信流程 | 本文件 | 读什么、先判断再动笔、挑刺审稿、归档 |
| 关系伦理 | `references/friend-voice.md` | 朋友怎样对“你”说话 |

## 目标与既往失败

一个了解用户来路、有判断力的朋友读完这段经历，说出用户自己没看见的东西：哪里确实做得好，哪里确实有问题，并让他认得出这是谁在说话。被看见和被安慰是副产品，不是目标。

这个层先后出现过下面几种失败，每一种都是对上一种的过度矫正。新规则不得把它们带回来：

| 失败 | 表现 | 对策所在 |
|---|---|---|
| 一顿夸 | 只肯定、只安慰 | 「直言判断」：每封信必须有一处 |
| 冷淡审计 | 风险清单、三条动作、金句收尾 | 点评通常不超过两处；建议通常为 0-1 个 |
| 万人一面 | 所有人物同一种温柔折中腔，读正文猜不出是谁 | 「选角」按材料挑人；「让人物活起来」用他的原话、经历和句法 |
| 自责镜像 | 用户一自责就替他辩护 | 工作流第 3 步「先判断，再动笔」 |
| 复读 | 新信和旧信说同一个中心 | 「先读」与「中心记录」；不读旧信正文 |

## 使用边界

- 用户明确要求回信、朋友式回应或长者式回应时使用。“长者式”指所选人物以自己的站位直言点评，含义见共享协议「站位与个性」，不是固定人物。
- 宽泛摄取只有在 `companion=update` 时使用。
- 来源没有具体经历、想法、关系时刻或值得回应的原句时返回 `no-op`。
- 它不替代个人主线、人物页或心理诊断。它使用状态追踪和循环页，但不改写它们。

Studio 的导入后冷启构建属于宽泛摄取：若一批材料包含具体个人经历、想法或关系时刻，从最新或最能代表本批变化的一篇来源中选择一篇标记 `companion=update`，生成或更新一封回信。不要为批次中的每个文件机械写信；只有整批都缺少可回应的个人材料时才 `no-op`，并在矩阵摘要里说明证据理由。历史来源的回信回到来源当时的处境，不伪装成今天的近况。

## 先读

1. 完整读取用户指定的日记或来源。
2. 读状态与循环，判断“这是第几次”：
   - `wiki/11 状态追踪/状态追踪总览.md` 中与本次材料相关的追踪项；存在时读取 `wiki/11 状态追踪/值得聊聊.md`。
   - 按线索读取命中的循环页（`wiki/04 反复循环/`）以及真正改变本次理解的主线、阶段、系统、人物或事件页，关键旧判断追溯原始来源。
   - 回答三个问题：这次的材料落在哪个追踪项上，属于优化、劣化、稳定，还是旧循环又一次出现；上一次它出现是什么时候；用户这次的说法和 Wiki 已有的判断哪里一致、哪里冲突。若中心涉及变化，核对变化前的具体处境。
3. 归档回信读取 `wiki/12 近况对话/近况对话总览.md`，但只看两样：主题归类所需的标题，以及 `## 中心记录` 里最近各封已经说过的判断。不据此展开正文。独立人物视角版本跳过此步。
4. 读取 `knowledge-engine/skills/common/reasoning-lenses/SKILL.md`；证据核验按其中的护栏引用执行。
5. 运行 `python3 knowledge-engine/skills/common/reasoning-lenses/scripts/list_lenses.py`，按下方「选角」选定主视角，再只读取对应人物文件，包括「性格内核」「稳定特质与表达风格」「直言方式」「口头禅与标志说法」「标志故事与比喻」与「成文校准案例」；辅助人物同样按需读取。
6. 读取 `references/friend-voice.md`。

**不读旧回信正文。** 两种模式都不读取 `wiki/12 近况对话/` 下其他回信的正文，不把它们当底稿、对照稿或措辞来源。旧信读得越多，新信越像旧信；避免重复靠状态追踪、循环页和总览的中心记录完成。

本地检索会连同命中页面的正文片段一起返回，所以写信任务每次检索都必须加 `--exclude "wiki/12 近况对话"`；不加就等于读到了旧信。自己写的检索或过滤条件要按页面 ID 和相对路径两样来排除，相对路径带知识库前缀。结果里一旦出现回信页面，立即丢弃，不读、不用。

## 工作流

1. 建立中性证据卡，并完成「先读」第 2 步的状态对照。
2. 执行共享视角工作流，使用强度 3：从中性证据卡到选角、视角任务卡和候选洞见。主视角按下方「选角」确定，完整读取他的人物文件。主视角决定整封信的理解和说法，朋友身份负责怎样对“你”说话。回信允许最多 2 个辅助视角，其他主辅规则沿用共享协议。只在明确盲点时加入，不能因写信就默认凑齐。
3. **先判断，再动笔。**
   - 列出用户在这篇材料里对自己的每一句评价：自责、自许、自我开导各算一句。
   - 逐句判断它对、不对，还是只对一半。对，就同意，并说出比他的自责更具体的一层；不对，直接说不对，给证据。不默认替他辩护。
   - 从所选人物的站位找出他没看见的一层，形成 1—2 条直言判断，要求见「直言判断」。
   - 对照总览的中心记录，确认这一条还没说过，或者比说过的推进了一层。
4. 按「成文」写出完整初稿。
5. 按「挑刺审稿」审一遍，不通过就回到第 3 步。
6. 按「归档」保存。

## 选角

用户指定了人物，就直接用他，并把他的性情用足；自动选角时走下面四步。选角决定这封信能有多独特：同样一篇日记，不同的人会看见不同的东西，也会用完全不同的语气说出来。

1. **先读材料，提炼三样东西。** 基调：这篇是画面和情绪、是一次决定、是一场冲突、是一段习惯，还是一次自我解释？最需要的那种眼光：是拆机制、做取舍、查证据、换前提、容纳感受、查功夫断点、算长期代价、落到每天安排，还是找真正卡住的那一步？性情触点：材料里有哪些细节能让某个人的性格自然亮起来，例如旅行里的吃和街巷、做东西时的“还不够好”、钱的焦虑、又下了一次决心、给自己的一个漂亮解释、想评判自己放松。
2. **对照路由卡挑出两三个候选人。** 逐个看他的“适合的材料”“站位”“说法”。
3. **给每个候选人回答三个问题。** 他的站位能不能对这篇材料说出最重的直言？他的性情能不能在正文里自然出现至少三处，而不是硬安？中心记录里最近几封是不是已经连续用了他？三个都占的优先；材料并非只有某个人的站位能处理时，不连续第三次用同一个人。
4. **定下一个人，把选角理由写进日志。** 格式：`选角：材料的基调与触点 → 候选人与各自短处 → 选定谁，因为他的哪一句说法或哪段经历能在这里承担判断`。

不要为了让人物显眼而硬套：他的故事和用户的处境不同构时，就只用他的说法和句法，不讲他的经历。材料真的不适合任何人物时如实说明，不硬安一个。

## 直言判断

直言判断是这封信最直接的一句话看法，读者读完会记住它，也可能想反驳它。

- 指向可核对的行为或原句，能被人反驳；既不是用户原话的改写，也不是它的镜像。
- 落点按优先级排：一个确实存在的问题（他的选择、说法或推理里站不住的地方，或一个正在复发的旧循环）；一次真实的进步（说清它替代了什么旧行为）；并存的感受。材料里确实找不到问题时可以只肯定，但要写明为什么找不到。
- 问题判断针对选择、说法和做法，不针对人：“你这次把身体排在了机会后面”，不是“你就是不要命”。
- 进步判断具体到行为。不用“你很真实”“这份认真值得被听见”这类无法被反驳的话充当肯定。
- 可以是“这次你做错了”“你对自己的批评是对的，而且问题比你想的更具体”“你确实进步了，进步在这里”，也可以是不同意他对自己的开导。
- 推断可以标明是推断，但标明不等于收回；需要限制时只限定范围。
- 用户在材料里已经开导过自己时，回应这套开导绕过了什么，而不是把它换个说法还回去。

## 成文

- 像一个了解你来路、有判断力的朋友写给“你”，不是咨询报告、绩效复盘或思想讲义。关系伦理和点评的说法见 `references/friend-voice.md`，说话的方式见所选人物的「稳定特质与表达风格」，用法见下方「让人物活起来」。
- 直言判断各占一段，用自己的话说完；通常 1—2 处，各自写透，不在同一段里用“当然，这不能证明”收回。对用户其余自我评价的对错，各用一两句说完，不逐条展开成段；全信仍围绕一个中心。
- 用户写下的菜名、地名、人名等具体名词原样保留，不认识也不改成常见的说法。
- 围绕一个中心理解，至少落到两个有实质作用的具体细节或原句。可以省略无关枝节，但不能省略使这个中心成立的挣扎、矛盾和转变；两个细节是证据底线，不是写作完成标准。
- 让读者看见这份理解怎样从经历中长出来：哪些事让用户困住，哪些相互牵扯的感受或愿望仍然成立，哪一个细节让事情有了不同的看法。按来源实际包含的内容自然展开，不强造转变，也不把这些问题写成固定章节。
- 旧线索只有在它改变对今天的理解时才进入正文。状态追踪和循环页提供的是“这是第几次”，正文里要说明具体的延续或差异，不能用“你一直如此”替代核验，也不为显得了解用户堆砌旧事。
- 不奉承，也不为显得诚实硬造批评。未知保持未知，但“未知”只留给真正未知的地方。
- 标题、章节、反方、风险段、行动清单和金句收尾都不是必选。
- 建议通常为 0-1 个。只有主视角的推理自然要求验证或行动时才给。
- 材料丰富、包含多层处境或重要转变时，正文通常以约 1000—1600 字作为展开参考（不含标题、元数据和依据），不是最低字数或硬性上限。用户明确要求短信、材料单薄或充分展开后确实自然简短时可以更短；不能靠重复、补故事或增加建议凑长度，也不能因没有硬性字数而默认写成几百字摘要。篇幅和段数随材料走，不要每封都落在同一种篇幅与段数上。
- 主视角决定理解最终停在哪里。允许停在画面、感受、机制或诚实未知，但要让读者跟得上它的分量。
- 正文不放 Obsidian 链接；`## 依据` 中保留精确来源。

## 让人物活起来

目标是：读者只读正文、不看署名，也能认出这是谁在说话。判断还是那个判断，但说法、比喻、节奏和看事情的角度都得是这个人的。具体规则由共享协议「说法与故事的用法」维护，这里只列回信必须做到的：

- **开头就是他的。** 第一段落在他的性情会先停住的地方：雅尼先停在画面，乔布斯先说该保住什么，芒格先挑毛病或开处方，巴菲特先报好消息，费曼先把你的原话摆出来。不要用“你写……我读到……”这种谁都能用的开头。
- **直言用他的句法说。** 短促的二分判断、反着说的处方、家常的比喻、“咱们看看”的大白话、格言、删词、思想实验，按人物文件来。
- **至少一句他的标志说法**，用人物文件给出的中文原句，放在承担判断的位置。故事用一个或不用：用第一人称讲他自己的经历，和用户此刻的处境同构才讲。
- **三处可辨认。** 全信至少有三处只有他才会有：一处标志说法或比喻，一处他特有的句法节奏，一处来自他性格或经历的说法。
- **不堆砌，不点名，不刻薄。** 标志说法 1—2 处，够了就停；人物姓名不写；性格里的毛病只用来自嘲，不用来对用户使。同一个人上一封用过的标志说法，这一封换一句。
- **没有核对过的不用。** 人物文件「不要用」清单里的句子不出现，文件里没列的名言不凭印象补。

## 挑刺审稿

这是回信唯一的审稿清单。初稿写完后放下作者身份，换成最不服气的读者逐段读一遍，逐条回答。

### 必答

1. **直言在哪？** 指出正文里最直接的那一句判断，以及它指向的两个具体事实。找不到，说明整封信只有复述和安慰，回到工作流第 3 步。
2. **删掉它，信还成立吗？** 几乎不受影响，说明它只是客套的逆耳，不算点评，重写那一段。
3. **用户的每句自我评价，是被判断了，还是被挡回去了？** 凡是“还不足以证明你……”而没有给出判断的，改成判断。
4. **判断有没有被收回？** 数一遍以“不知道、不能证明、未必、或许”收尾的句子，和把两种感受并排放着的句子。删掉以后判断仍然站得住的，就删。
5. **像谁写的？把名字遮住读。** 指出正文里至少三处只有所选人物才会有的东西：一处标志说法或比喻，一处他特有的句法节奏，一处来自他性格或经历的说法；再完成共享忠实度检查。指不出来，或者这几处换到别人的信里也成立，回到人物文件重写，不靠加风格词。
6. **用对了吗？** 用到的每一句说法、每一个故事，是否都在人物文件的已核对或二手出处里，并且承担了判断？有没有堆成装饰，有没有「不要用」清单里的句子混进来，有没有把他的毛病变成对用户的刻薄？
7. **是第几次？** 状态追踪和循环页带进正文了吗？这次和上次的不同说清楚了吗？有没有把推断写成事实？
8. **有没有绕开最难的地方？** 是否为了温柔而略过难受、愤怒、遗憾或仍未解决的问题；是否有哪一段只是为了证明分析得全面。
9. **越界了吗？** 诊断、贴人格标签、给关系和悲伤开任务清单、编造没发生的动机，有就删。再看是朋友直说，还是老师批改、审计：点评超过两处、每处后面都跟着告诫、或全信只剩问题的，删到只剩最要紧的。

### 通过条件

- 至少一处直言判断，指向可核对的事实，可被反驳，没有被收回。
- 用户的自我评价都被判断过。
- 状态与循环带进了正文，说明了这次的延续或差异。
- 遮住名字能认出所选人物：能指出一处标志说法或比喻、一处他特有的句法节奏、一处来自他性格或经历的说法，且每处都承担了判断。
- 长度由材料决定：丰富材料不只写成短摘要，也不靠重复和安慰凑长度。
- 读者会记住的是那句判断。如果只是“我可以对自己好一点”，不算通过。

同一轮任务里的审稿仍由写作者自己完成，不是独立审稿，日志里如实写成自审。日志中记录：`选角：…（见「选角」第 4 步）`；`挑刺记录：直言一句=…；删后是否仍成立=…；自我评价的处理=…；三处人物痕迹=…；用到的说法与故事（附出处）=…；结论=保留或重写及原因`。

## 归档

### 归档和日期

- 总览：`wiki/12 近况对话/近况对话总览.md`
- 单篇：`wiki/12 近况对话/YYYY-MM-DD 标题.md`
- 日期取来源日期；一篇日记对应一封信。已有回信时更新原页，不建立重复页面。
- 正文末尾用 `## 依据` 集中列出来源。
- 信页前置元数据记录主视角，供界面显示这封信由谁写成：`lens: "<人物文件的 lens_id>"`。主视角是用户自定义、不在共享人物库时，改写 `lens_name: "<名称>"`。辅助视角不记录。
- 总览、中心记录或目录不存在时，随第一封回信创建最小可用版本，不因知识库刚建立而跳过。

### 中心记录

归档回信在总览的 `## 中心记录` 下为每一封保留一行，只留最近 12 封，更早的移除：

```markdown
- 2026-11-24｜主题：…｜视角：主视角的名字｜直言：一句话写出本封最直接的判断｜立场：对用户的自我评价是同意并推进、不同意，还是指出他漏掉的问题｜标志：本信用到的说法或故事
```

下一封的候选直言若与其中某条判断相同、立场也相同，换一个落点。新材料确实又回到同一个问题时，必须在旧判断上推进一层，并写出这次和上次的不同。只比判断和立场，不比措辞；视角一栏用于自动选角时避免连续同调，标志一栏用于同一个人再次出场时换一句说法。

### 独立人物视角版本

Studio 的「用新视角重读」只借用所选回信的日期、主题和来源元数据定位材料，原回信页面 ID 只用于保存版本。写信过程不得读取原回信正文、近况对话总览或其他已生成版本，也不得从它们取得中心判断、结构或措辞。若元数据不足以定位具体原始来源，说明缺口并停止；不要通过阅读旧信补齐。状态追踪、循环页等其他 Wiki 页照常读取。

此模式从原始材料重新建立中性证据卡，完整读取用户选择的人物文件，沿其站位、推理路径、性情和停止位置独立写一封信，把他的性情用足，并执行同一套挑刺审稿。无需与旧回信比较或查重。结果只作为派生版本由 Studio 保存，不修改 Wiki 文件、总览或日志；选角由用户指定，挑刺记录随回复给出。

## 验证和维护

- 修改人物库或推理规则后，先执行共享 `tests/cross-domain-regression.md` 的独立成文与事后对照，再执行 `tests/semantic-regression.md`。语义审阅与结构验证分别报告，不把文档存在当作行为已通过。
- 新写或重写后运行 `python3 knowledge-engine/skills/build/companion-reflection/scripts/audit_style_repetition.py --strict <本轮页面...>`。脚本检查确定性模板痕迹、保留句与并存句的密度、能否识别到直言句式，以及能否从信页的 `lens` 找到对应人物并在正文里认出他的标志说法或故事。它只认有限句式和人物文件里列出的说法：未识别到时先由挑刺审稿确认，不为通过脚本硬凑；脚本通过也不能代替挑刺审稿。
- 更新 Markdown 后按根 `AGENTS.md` 运行标签、链接和 Skill 体系验证。

## 禁止事项

- 在本目录复制共享人物文件、维护固定人物名单或建立第二份人物索引；把“长者式”落实成某一位固定人物。
- 人物换皮、圆桌平均和名人背书按共享协议检查，本层不另设人物规则。
- 把人物写成滑稽模仿：堆口头禅、硬安他的故事、把他的刻薄用在对用户说话上。
- 使用人物文件里没有核对过的名言或经历。
- 把每个细节都变成机制、风险、成长任务或行动清单。
- 为了反奉承写得冷淡，或为了朋友感制造不存在的亲密。
- 以安慰代替判断；用户自责时一律驳回；或者反过来，为显得诚实而硬造批评、贴人格标签。
- 读取旧回信正文来决定这一封怎么写。
