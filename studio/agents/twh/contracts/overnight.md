# 过夜合同

把尖括号里的内容换掉，整段发给入口：`/twh-mode`，或直接说"按本仓流程"。

```text
我要去睡了。<目标，一句话>
done means <能跑的判定：命令、数字或文件状态>。
每个任务在独立 worktree 里做，从最新的 origin/main 切出，一个任务一个分支。
记决策日志。提交不用问我。
循环直到 done。
卡住超过 <N> 轮就停下，写清楚卡在哪、试过什么。
```

## 发之前核对

四项都成立才发。缺一项就先在你看着的时候跑。

- [ ] 这类活我亲手做过一遍，或看着 Agent 做过一遍，知道好的结果长什么样。
- [ ] Agent 有我自己会用的工具和信号：`verify-twh`、`pnpm gate`、日志。
- [ ] 每一步都能自证，并且能停下线。
- [ ] 我读过几份运行记录，把重复失败变成了检查。

时长不是完成判定。"跑四个小时"不写进合同。

## 档位

- `stack`（默认）：只产出自带裁决书的分支，早上操作者合。
- `full`：连续 5 晚干净后放开，裁判通过后自动推 main。第一晚开 `full` 之前，先跑过一次 `stack`。

## 循环

每轮做五件事：查完成判定；在当前 HEAD 上做证据支持的最小改动；对着真实产物实跑；有进展就提交，没收益就丢弃；记一行决策日志。

平台期不是停止信号，换方向继续推。不放宽完成判定来宣布胜利。运行中发现的旁支问题（坏了的 skill、不稳定的验证脚本、工具故障）自己修，单独一个提交，修完回到主线。

## 停下来的时候

只在这几种情况下停：真正的死路；要部署、删数据、迁移真实数据；要操作者做的产品决定。停下时按 Pause safely 剧本写 `wip:` 提交和交接说明。

## 早上

`/show-me-your-work` 读决策日志，换一家模型复核，回复带 Attention 段。`/ketchup` 说改了什么、哪些等你定。

## 边界

过夜不碰个人知识库。不发布。不迁移真实数据。只驱动本次运行自己启动的匿名实例。
