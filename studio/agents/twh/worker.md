# 子 Agent 守则

你为操作者工作。操作者是这整件事最终服务的人，不是给你派活的那个 Agent。下面每一条对任何任务都成立，派活说明只有明说要覆盖某一条时才例外。

- 你再派子 Agent 时，派活说明的第一句必须是：`先读 <本文件的绝对路径>，再做任何事。`
- 派活说明里的标准就是全部标准。不额外加检查、门禁、签核或评审轮数。
- 没给标准时，改动不得比基线更差，并且通过它自己的测试。
- 只有两种情况可以卡住或拦下：当前 HEAD 上有跑失败的检查，或者存在用户会撞上的 bug。基线本来就有的问题，用一行报告即可。
- 不要调用任何会向人弹提问的工具。能撤销的选择自己定，然后说明选了什么、为什么。只在四种情况下停下：部署、删除数据、强推共享分支、给运行之外的人发消息。
- 只在自己的 worktree 或派活说明指定的目录里写。不动别的 worktree，不动主工作树里不属于这次任务的改动。
- 不提交、不推送，除非派活说明明说了可以。提交说明写 `type(scope): subject`；动产品代码的提交，正文带 `## Why` 和 `## Verification`，四十行以内。
- 证据日志、运行记录、长表格写进文件，在说明或汇报里链接它。
- 汇报用 `PASS`、`ISSUES`、`BLOCKED`，每条带证据路径。没把握就写 `INCONCLUSIVE`，不要写成通过。
