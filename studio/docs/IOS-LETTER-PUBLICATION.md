# iPhone 回信发布边界

手机回信的只读生成完成后，`runtime/mobile-sync/letter-finalization.ts` 才处理发布。它检查任务、Run、配置快照、冻结资料的知识库、路径、ID 和 hash，并从冻结正文重新计算 hash。范围解析来自共享知识索引；它不按当前界面活动库扩充来源。

引用使用 wiki-core 的共享 `extractWikiLinks` 与 `validateFrozenSourceReferences`。只接受冻结目录中完整来源路径，引用标签、段落锚点和连续原文必须可核对。范围外、其他知识库、额外链接、假引用及假引文均阻止发布。双引号和引文块在此输出协议中只表示逐字原话；假设使用普通文字并标明推断。来源统计只包括正文实际引用的来源。实际引用的来源在质量门前和提交前都必须仍是当前绑定空间中的普通文件，任一层 symlink、移动或删除会要求重选范围；不会读取 live 正文或检查未引用来源。正文编辑仍使用冻结原文，成品元数据记录冻结时间与 hash，避免把旧快照冒充当前内容。

发布前，宿主在 Mac 私有状态目录建立隔离候选工作区，通过公共 `runValidationCommands` 调用共享 `validate_wiki_links.py`。该目录只含候选、冻结来源的目标占位文件和共享校验代码；不会读取实时来源，也不对真实 Wiki 运行标签更新。原始冻结正文仍留在独立证据文件中，供 hash 与引文验证。这是确定性链接质量检查，不能代替共享回信 Skill 要求的语义和人物视角审稿。

成功候选通过临时文件和独占 hardlink 提交。目标已存在时，必须字节一致才视为幂等成功；差异不会被覆盖。失败候选、绑定信息及诊断保存在 Mac 私有状态 `mobile-letter-candidates/<task>/<body-hash>.json`，不会作为 Wiki 成品发布。任务回执标明失败、清空结果路径，并保留生成文字供核对。

匿名测试覆盖跨库、冻结内容变化、范围外/假引用、假引文、真实共享链接质量门、相同目标重放及修改冲突。所有测试使用临时目录，不访问实际知识库、iCloud 或模型密钥。
