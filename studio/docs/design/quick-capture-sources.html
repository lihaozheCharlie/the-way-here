        设计说明

        上方卡片为可交互原型；用顶部“状态预览”可直接跳到每个状态。以下是设计思路与规则。

        一、核心思路：随手记 = 一条记录 + 若干材料

        现在的随手记只有“说 / 写”一种输入。要承载找照片、将来的看日历和连接其他 App，不能每加一个能力就多一块卡片。所以把卡片拆成三个稳定的概念：

        来源（Source）取得材料的一种方式：说或写、找照片、看日历……用顶部的来源切换器选择，一次只展开一个。
        材料（Material）来源产出的东西：文字、照片、日程……统一放进“材料托盘”，样子不同，但进出规则相同。
        记录（Record）用户最终保存的那一条。无论从哪个来源进来，都走同一个“整理并保存”和同一个保存目录。

        好处：新增来源只需要提供“一个面板 + 一种材料样式”，标题栏、托盘、动作行、页脚都不用改；用户的心智也始终是“我在写一条记录，顺手把素材带进来”。

        二、卡片结构

        1. 标题栏（不变）：“随手记”+ 状态徽标 + 历史记录。徽标逻辑沿用：新记录 / 待整理 / 补充中；只有材料没有文字时也算“待整理”。
        2. 来源切换器（新增）：胶囊分段控件，直接复用项目里已有的 .segmented-tabs 视觉（浅蓝轨道 + 白色滑块）。标签用“动词 + 图标”，与现有按钮“说一段 / 找照片”保持同一语气。
        3. 来源面板（按来源切换）：说或写面板保持现状；找照片面板是本次新增；其它来源以后同样放这里。
        4. 材料托盘（仅“说或写”面板显示）：在文本下方，一排日程小卡等“附在这条记录上”的轻材料，可逐项移除。照片不进托盘：照片有自己的“认人 → 讲故事”流程，选好后直接带去整理（见下一节）。
        5. 动作行（不变）：说一段 / 暂存 / 整理并保存。
        6. 页脚（不变）：保存目录 + 状态文字，各来源只更换状态文案（如“选中后才会加入记录”）。

        三、找照片面板：把 demo 的 9 个控件分成两层

        第一层 · 一眼可见时间（附 4 个常用时间快捷）、拍摄地点（附近范围仅在填了地点后可选）、搜索。覆盖“上个月 / 去年 / 在杭州”这类最常见的回忆线索。
        第二层 · “更多筛选”折叠时间依据、起止日期、相册（含刷新）、照片类型、仅看收藏。折叠时，已生效的条件以蓝色小标签显示并可单个移除，不会“藏着筛选而不自知”。

        结果与选择

        • 结果区最高 372px，内部滚动；“已选 N 张”条始终吸附在底部，不会被滚走。
        • 点击缩略图 = 选中 / 取消（左上角圆形勾选）；放大查看用右下角按钮，打开与“历史记录”同款的弹窗，可在大图里直接选择。
        • iCloud 照片在格子里显示“下载预览”，不自动联网下载。
        • 单条记录最多 50 张。选择条显示“已选 N / 50 张”；达到 50 张后，未选缩略图变灰且不可再选，选择条提示“已达上限”，大图弹窗里的按钮也变为“已达 50 张上限”。仍想点选时，列表上方会出现一行提醒。
        • 选中不等于保存。点“整理成照片记忆”才会把选中的照片带去整理。

        授权与平台

        “找照片”依赖 macOS 系统照片库，非 macOS 时整个“找照片”标签直接隐藏，不出现入口也不出现说明块；只剩一个来源时，来源切换器也一并隐藏，卡片退回现在的“说或写”样貌。macOS 下的首次授权 / 已拒绝两种状态仍在同一面板内以说明块呈现，文案沿用现有实现。（用顶部“平台”可对比两种情况。）

        三·补、照片的去向：选好后接入现有“导入照片”流程

        选择条的主按钮改为“整理成照片记忆”，点击后不离开此刻页面，直接打开已有的导入与照片记忆流程，复用现有页面，不新做一套：

        1. 带一段记录进来：已选照片以缩略图条展示，填写记忆名称，确认保存到“生活记录 / 照片记忆”，右侧是文件数、大小的核对摘要。系统照片库里的 HEIC 自动导出为 JPG 后导入。点“开始认人物”时才真正导入。
        2. 认人（圈选）：与现有一致，实线框是已标注人物，虚线框是待认领，可拖动缩放，也可“圈选漏掉的人”，认出的人在同组照片里同步更新；可跳过。
        3. 讲故事：补充线索后点“AI 帮你写”，AI 把全部照片串成一篇故事，用户核对修改后“收进理解”。
        4. 完成：弹窗关闭，随手记卡片回到“找照片”并清空已选，卡片底部提示“已生成生活记录「…」”，可直接查看。

        导入后中途关闭不会丢失：照片记忆已建立，可从历史记录回来继续。弹窗是为了在设计稿里呈现；落地时也可直接跳转到现有的照片记忆工作区页面。“状态预览 → 带去整理”可逐步查看。

        四、交互规则

        场景规则
        切换来源各来源的输入、筛选条件、搜索结果、已选项全部保留，切回来继续；不弹确认。
        录音中其他来源标签置灰不可点，避免录音和筛选互相打断；完成或取消录音后恢复。
        材料进入记录日程等轻材料通过面板里明确的“加入这条记录”进入；照片通过“整理成照片记忆”进入导入流程。搜索或选中本身不会自动写入任何东西。
        照片数量单条记录最多 50 张，超出前拦截，不允许“先选再删”。
        非 macOS“找照片”标签隐藏；只剩“说或写”时来源切换器也隐藏。
        移除材料托盘里每项右上角 × 移除，仅从这条记录移除，不影响原日程；照片在选择条里点“清空”或取消勾选。
        保存仍需有文字才能“整理并保存”（保持现有产品原则：记录以用户自己的话为主）。
        键盘来源切换器支持 ← → 切换；缩略图是可聚���按钮，空格 / 回车选中；搜索框回车触发搜索。
        动效仅切换器滑块与展开箭头有 200ms 过渡；尊重“减少动态效果”设置。

        五、未来来源如何接入

        在“状态预览 → 未来”里可以看到一个“看日历”的示意：它复用了完全相同的切换器、面板外壳、底部“已选”条和材料托盘，只多了一种日程小卡。新增来源按下面清单设计即可：

        • 标签：一个图标 + 两到三个字的动词（看日历、连接 App）。
        • 面板：顶部一句说明 → 常用条件前置 → 低频条件进“更多筛选” → 结果列表 → 底部“已选”条。
        • 材料样式：定义托盘里一项长什么样（64px 高，右上角 × 移除）。
        • 授权与隐私：未授权 / 被拒绝 / 不支持三种状态，用同一个说明块；面板底部写一句“读什么、不做什么”。
        • 数量上限：切换器最多直接显示 4 个来源，第 5 个起收进“更多 ▾”菜单（尚未开放的来源以“即将支持”标记，不可点）。

        六、与现有风格的对应（未引入新的视觉语言）

        • 颜色全部取自 theme-tokens.css：蓝色只用于交互与选中，未新增任何色值。
        • 卡片壳、标题 22px/700、徽标、页脚底色、说一段按钮、录音条、“整理并保存”主按钮均沿用现有尺寸与圆角（20 / 14 / 11px）。
        • 输入框 38px 高、--radius-control 圆角、13–14px 字号，与 demo 的表单控件规格一致；次要按钮与 demo 的 desktop-secondary 一致。
        • 原先独立的“从一张照片想起”卡片在新设计中并入随手记，此刻页面只保留“陪伴卡片 + 随手记”两块。

        七、需要你拍板的问题

        1. 一键收进理解的命名最后一步沿用现有按钮文案“收进理解”，保存后在此刻页提示“已生成生活记录”。若希望与卡片里的“整理并保存”统一措辞，只需改按钮文字。
        2. 照片选择与流程的承载方式设计稿用弹窗承载“确认位置 → 认人 → 讲故事”。若现有照片记忆工作区已是独立页面，落地时直接跳转即可，卡片部分的设计不变。
