# Mac 桌面端

Mac App Store 上架材料、个人开发者账号协作步骤和商店版工程阻塞项见 [上架操作手册](app-store/README.md)。以下现有 DMG 打包流程用于商店外测试，不能直接用于商店提交。

The Way Here 由 Electron 主进程托管知识运行时和 React 工作区。客户端通过私有消息通道访问共享业务能力，不监听本地端口；Web 版使用独立 HTTP 入口。窗口使用系统标题栏按钮、系统菜单和本机文件选择器。首次启动自动创建本机知识空间；已有用户继续打开原来保存的位置。应用包不包含任何私人材料。

## 开发与打包

在 `studio/` 内运行：

```sh
pnpm install
pnpm desktop
```

`pnpm desktop` 构建前后端、编译 macOS 语音辅助程序及图标，然后通过 `.runtime/desktop-dev/The Way Here.app` 打开应用；开发包使用独立副本和正确的系统名称，不修改安装的 Electron 依赖，Dock 悬停显示 The Way Here。需要 macOS、Xcode Command Line Tools、Node.js 22.19+、pnpm。AI 继续使用本机 Codex 登录或偏好设置中的第三方模型配置；没有配置 AI 时，浏览、搜索、记录和导入仍可用。

```sh
pnpm desktop:package
```

产物位于 `studio/.runtime/releases/`，包括 Apple Silicon DMG。打开 DMG 后将应用拖入“应用程序”。首次运行无需选择配置文件或安装开发工具，默认打开随包附带的匿名演示知识库，不创建空白的“我的知识库”；包内没有工作区里的私人知识库或个人记录。旧版安装留下的空白“我的知识库”会在确认没有记录和自定义设置后移除。包内包含 Electron、前后端、原生语音组件、知识引擎，以及可重定位的 CPython 3.12.13 / PyYAML 6.0.3。打包机器额外需要 `uv`（可用 `TWH_UV` 指定）。打包结束会检查应用中的所有符号链接，确保它们均指向应用包内部。

默认数据位于 `~/Library/Application Support/The Way Here/workspace`，原始记录和生成的 Wiki 分别保存在 `app/<id>/sources`、`app/<id>/wiki`。外部连接的原文件仍保留在原目录。支持客户端内更新的版本会在侧栏偏好设置右侧提示下载，点击后显示进度，校验完成且当前工作已保存后自动重启安装；不会重置配置、记录或连接。旧版客户端首次迁移仍需手动替换 `.app`。应用管理的知识引擎在启动时更新，用户的配置及根协议保留。

“文件 → 打开已有知识空间…”是旧知识空间的可选恢复入口；普通资料目录应在首页或“资料”中连接。保存的旧位置失效时显示恢复选择，不会静默创建空库。开发启动仍默认使用源码工作区；`THE_WAY_HERE_VAULT` 可显式指定测试工作区。

`desktop:package` 生成未签名、未公证的测试 DMG。应用依赖已验证可在脱离开发目录的路径下启动，但另一台 Mac 的 Gatekeeper 仍可能拦截这个测试包。官网正式发布改用独立的 `pnpm desktop:release`，强制 Developer ID Application 签名、公证及 Gatekeeper 验证；原测试配置保持独立。准备、凭据与下载页流程见 [DIRECT-DISTRIBUTION.md](DIRECT-DISTRIBUTION.md)。测试前应核对收到的 DMG 的 SHA-256，不要对来源或哈希不明的应用绕过系统安全检查。

### 此刻 · 系统照片库

“从一张照片想起”卡片展开后检查访问状态，由“允许访问照片库”触发系统授权。筛选可组合：时间、用户相册、仅看收藏、照片类型和拍摄地点。时间可写“去年”“最近30天”“2024年5月”，或使用包含结束日的起止日期；支持 macOS 26 的设备可选择“加入图库时间”，默认按拍摄时间。相册直接从系统照片库读取，可刷新，不再按文件名搜索。类型包括全部照片、实况、截屏、全景、人像模式、RAW、连拍；人像模式不代表人物身份。地点由 Apple 原生地理编码定位，范围可选 1/5/10/30/100 公里，仅匹配已有位置的照片，不代表行政区边界。结果每页 36 张，可继续加载，分页沿用提交时的全部条件。清除筛选后再次搜索可浏览全部照片。人物标注、说明、关键词及画面内容搜索暂未接入，不依赖外部工具。

点击照片可在结果上方查看大图；iCloud 照片默认不下载，需要点击“下载预览”。收起、离开、切换知识库后清除内存结果，不导入知识库、不发送给 AI、不修改原照片。拒绝授权时可打开系统设置并重新检查。浏览器与非 macOS 只提供不可用说明和原有导入路径。

验证：`pnpm typecheck`、`pnpm test`、`pnpm build`，原生组件由 `pnpm desktop:native` 编译；`node scripts/verify-photo-library.mjs` 使用临时匿名 demo 和模拟照片 IPC 验证卡片交互与截图，不访问真实照片。发布前须用签名开发包在 macOS 15 和当前系统实测首次授权、拒绝/撤回、HEIC、iCloud、定位缺失、分页和图库切换，确认辅助程序继承沙盒与授权归属。当前工程接入不代表这些真实图库和 MAS 场景已经验收。

所有录音入口最多录制 20 分钟，可随时再次点击结束。原生识别每 50 秒换接一段请求，麦克风连续采集，按顺序汇总各段文字，避免单次系统识别的一分钟限制。

语音识别需用户主动开始并授权麦克风及系统语音识别；设备支持时优先本机识别，否则由系统决定服务可用性。AI 整理通过已配置的 Agent 运行只读任务，不直接写原始记录或 Wiki。真实麦克风输入、AI 外部服务、通知展示和 iPhone 硬件不能由匿名自动验收替代。

## 打开已有资料目录

桌面端在「生活记录」文件夹栏或导入窗口底部点「打开文件夹」，选择真实目录并确认允许 AI 修改；直接访问和修改原文件，支持多级子目录，不提供日记文件或 ZIP 副本上传。聊天记录、消费账单和照片继续导入，保存到用户选择的应用内真实文件夹。Web 端需填写本地服务所在电脑的目录绝对路径。

- 普通目录中的 Markdown / TXT 保留原处，包含子目录；正文不复制进工作区。单文件上限 2 MB、单目录最多 10000 份，隐藏文件和符号链接不收录。
- 新建知识库使用 `app/<id>/wiki` 保存生成的 Wiki，`app/<id>/sources` 保存随手记、照片/账单缓存、一次性导入与轻量来源引用。原有 `vault/<id>` 配置保持兼容，不自动搬移已有资料。
- 外部文件支持在主窗口原位编辑，独立阅读窗口保持只读。在原来的编辑器中修改后，目录监听会刷新索引；按内容版本检测新增、修改和删除，同内容改名保留引用身份。
- 打开文件夹并授权后，后台将变更合并，使用已配置的 AI 按原有知识构建规则更新受影响页面。每批最多 50 份，与当前库任务互斥，始终绑定来源所属知识库。
- 没有可用 AI、运行失败或目录暂不可用时保留待更新状态并显示原因。AI 失败不会无限自动重试；调整配置后点击「更新 Wiki」。运行期间再次修改的文件会进入下一次更新。
- 文件消失后保留不含正文的失效来源引用，供已有 Wiki 追溯与复核。文件夹根菜单「从列表移除」只移除应用入口，保留原文件和 Wiki。删除整个知识库也只删除应用管理目录，不访问原目录。

自动化验收使用临时匿名原目录，覆盖零正文复制、外部编辑刷新、改名/删除、符号链接隔离、跨库任务、后台更新、离线/失败、重启和安全移除入口。真实 AI 生成质量仍取决于用户配置的模型与知识质量门。

## 全新安装验收

`node scripts/verify-first-install.mjs` 将实际安装包复制到临时 Applications 目录，用全新的用户数据目录启动，不提供工作区环境变量，并仅提供系统 PATH。验证默认打开 demo、只注册 demo、随包资料一致、Python 四项质量命令可运行，以及重启后继续使用同一空间。`pnpm desktop:verify` 先运行 Web 匿名功能验收，再通过真实 Electron 及 IPC 核对九个主页面、原目录打开与移除、导入菜单及快捷键。文件选择和授权对话框使用测试替身，真实系统授权及 AI 生成需单独验收。

桌面端演示内容直接从 Web 端的 `vault/demo` 打包，不从 UX 设计稿生成故事或数据。保留 Wiki、原始记录、照片、账单及隐藏附件目录，继续使用 `vault/demo` 路径以维持已有资源引用。首次启动默认打开 demo，旧版托管空间升级会注册缺失的 demo；已有 demo 和个人内容不覆盖。

## Mac App Store 的 Codex 连接

MAS 包包含固定版本的官方 Codex，无需选择外部可执行文件。在「偏好设置 → AI 助手 → 连接已登录的 Codex…」选择保存既有 ChatGPT 登录的目录；应用只复制登录材料到独立私有目录，原 Codex 的配置、插件与历史不会导入。此连接仅支持 ChatGPT 登录，其他模型继续使用第三方 API 配置。AI 共享许可默认关闭，需要另外同意才可发送任务。

商店版关闭 Codex 的原生 shell 与扩展能力，通过应用提供的受限文件工具访问本轮绑定的知识库。只读任务不能写文件；写入任务复用路径与内容版本检查。取消任务或撤回许可后，后续工具调用会被拒绝。开发签名构建与实际验收范围见 [MAS 验收记录](app-store/mas-validation.md)。

### 轻量系统语音识别

随手记使用 macOS 自带的中文设备端语音识别，不随安装包分发 Whisper、VAD 或独立模型，也不提供增强模型下载。开始前检查语音权限与设备端识别能力；系统中文资源未就绪时明确提示启用中文听写，用户仍可键盘输入。系统语音资源由 macOS 管理，不计入应用安装包；应用不会退回上传录音的识别方式。

录音时显示实时预览，并连续保存完整音频与最多 45 秒的分段音频。系统设备端识别可能在同一任务内多次返回已完成的单句话，之后从下一句话重新给出临时结果，甚至以空结果结束任务；实时预览和停止后的重识别共用按音频时间范围累计的状态，已完成的话保留，临时结果只修订当前一句，重复回调替换原有时间范围。实时任务提前完成或报错时自动开启新段，不等待固定分段计时器。停止后用系统识别依次重新读取各段并请求标点，显示已完成分段的进度；每段设 60 秒超时。最终结果可纠正预览中的重复；如果最终文字不足预览的一半，则视为疑似截断，保留较完整的预览、分段音频并明确提示。这是防止明显文字丢失的保守检查，不保证识别内容完整。失败段同样保留较完整的预览并明确提示。完整音频、预览和最终文字保留在应用数据目录 `cache/speech-recordings`，失败段也保留供恢复；可通过“打开原始录音”查看音频。取消跳过后处理，退出终止识别进程。音量波形仅代表声音输入。

回归可通过原生助手的 `<输出目录> --replay <音频路径>` 参数，将本机录音按原始速度逐帧送入同一实时录音与后处理流程，不启用麦克风，也不上传音频。`node scripts/verify-speech-replay.mjs <音频路径...>` 构建独立测试助手并保存本机结果，检查跨句累计、跨分段进度和完整音频帧数；加 `--pause-resume` 可对超过八秒的录音自动验证暂停、继续与帧数保留。历史录音及转写不得作为仓库测试夹具或发布产物。匿名单元测试覆盖句间重置、空 final、重复回调、累计回调、短文本修订和相同话语在不同时间重复出现。

`pnpm desktop:native` 只编译系统原生助手与品牌资源，不再下载语音模型或构建 whisper.cpp。语音准确率仍受发音、环境、姓名及夹杂英文影响，保存前应核对；未经真实录音对照评测，不声称优于原模型或云端服务。

“整理成日记”将最终原话整理成当天的第一人称日记，清理停顿词和无意义重复，保留事实、细节及原话；结合完整表达整合口误和改口，保留真实先后变化与不确定性；已有实体的姓名及人物关系片段用于核对语音错名，关系、时间与上下文均明确时规范姓名并关联，区分直属、上级的上级、新任与前任，同名或不明确的称呼保持文字。输入原话单独保存在应用缓存，不写入生活记录 Markdown。“只存原文、稍后再整理”把原文写成一篇生活记录，不调用模型，也不会覆盖已经整理过的文件。旧记录保持原样。


### 应用缓存与保留边界

桌面端统一使用用户数据目录下的 `cache/`：录音位于 `speech-recordings/`，按工作区隔离的随手记输入与旧版备份位于 `vaults/<workspace-hash>/capture-inputs/` 和 `capture-versions/`。非桌面运行使用现有工作区应用状态目录下的 `cache/`。输入按知识库与任务分别哈希命名，不进入 Wiki 索引。

`GET /api/storage/policy` 提供当前目录与清理分类，为后续缓存管理使用；目前没有自动清理或删除接口。可重建文件、条件保留材料和必要状态的完整约定见 [应用存储与缓存](STORAGE.md)。未保存的草稿、录音的唯一副本和恢复中的任务不能当普通缓存清理。


### 升级时保留用户配置

保存目录、语言、通知、照片默认目录、导入类型、目录树/正文导航偏好、模型配置引导状态、面板宽度和窗口位置尺寸纳入持久化清单，见 `USER-PREFERENCES.md`。桌面偏好位于应用用户资料目录，独立于浏览器 origin 和版本；文字默认目录独立于草稿历史，升级不重写现有值。旧设置按需导入，不替用户恢复或推测丢失的选择。配置写盘失败不确认保存成功，损坏配置不以默认值覆盖。

`node scripts/verify-preferences.mjs` 使用匿名资料与隔离 userData/sessionData，通过真实界面修改默认目录、语言和通知，并验证照片目录、导入类型、面板及窗口尺寸；清空测试 Chromium Local Storage、退出再启动后核对保留。`verify-native-update.mjs` 同时验证真实签名升级替换、重启后的实际 UserPreferences 与匿名草稿。两个脚本均在结束时清理本次测试进程、服务与资料，不访问用户当前配置。


随手记恢复旧草稿后首次保存，以最终生成/保存时用户所在时区的日期命名，而不沿用草稿初建日期。“只存原文”遵守同一规则。整理跨午夜完成时，文件名、日期标题及历史同步到最终日期；正文中明确提到的旧事件时间不变。已保存日记的继续补充保留原文件与记录日期。


### 标题编辑提交

标题（文件名）编辑中不启动定时重命名。用户停顿、移动光标或使用中文输入法时保持输入框与选择范围；按 Enter 或离开输入框才提交重命名，Esc 恢复已保存名称。重命名会改变页面身份，故不能套用正文的定时保存策略；正文仍按原流程自动保存。`node scripts/verify-title-editing.mjs` 验证键盘/鼠标光标、停顿、IME Enter、显式 Enter、Esc 和失焦保存，自动清理测试浏览器、监听端口与匿名夹具；`--expect-before` 曾在修复前复现定时重命名导致丢焦。
