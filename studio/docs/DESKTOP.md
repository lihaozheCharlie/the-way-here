# Mac 桌面端

The Way Here 现在由 Electron 主进程托管本地服务和 React 工作区。窗口使用系统标题栏按钮、系统菜单和本机文件选择器。首次启动自动创建本机知识空间；已有用户继续打开原来保存的位置。应用包不包含任何私人材料。

## 开发与打包

在 `studio/` 内运行：

```sh
pnpm install
pnpm desktop
```

`pnpm desktop` 构建前后端、编译 macOS 语音辅助程序及图标，然后打开应用。需要 macOS、Xcode Command Line Tools、Node.js 22.19+、pnpm。AI 继续使用本机 Codex 登录或偏好设置中的第三方模型配置；没有配置 AI 时，浏览、搜索、记录和导入仍可用。

```sh
pnpm desktop:package
```

产物位于 `studio/.runtime/releases/mac-arm64/The Way Here.app`（Intel Mac 为 `mac` 目录）。将应用拖入“应用程序”后双击打开。首次运行无需选择配置文件或安装开发工具，会自动建立“我的知识库”。包内包含 Electron、前后端、原生语音组件、从仓库权威来源打包的知识引擎，以及可重定位的 CPython 3.12.13 / PyYAML 6.0.3。打包机器额外需要 `uv`（可用 `TWH_UV` 指定）。

默认数据位于 `~/Library/Application Support/The Way Here/workspace`，原始记录和生成的 Wiki 分别保存在 `app/<id>/sources`、`app/<id>/wiki`。外部连接的原文件仍保留在原目录。更新只需退出应用、替换 `.app` 后重新打开；不会重置配置、记录或连接。应用管理的知识引擎在启动时更新，用户的配置及根协议保留。

“文件 → 打开已有知识空间…”是旧知识空间的可选恢复入口；普通资料目录应在首页或“资料”中连接。保存的旧位置失效时显示恢复选择，不会静默创建空库。开发启动仍默认使用源码工作区；`THE_WAY_HERE_VAULT` 可显式指定测试工作区。

当前打包配置生成供本机使用的未签名 `.app`。对外分发前，需要提供 Apple Developer 签名身份与公证凭据，移除 `mac.identity: null` 后执行签名、公证与分发打包。本机构建不冒充已公证安装包。

## 操作

| 操作 | 快捷键 / 入口 |
|---|---|
| 搜索记录、理解、栏目和命令 | ⌘K |
| 随手记 | ⌘N；菜单栏「此刻」 |
| 导入文件、对话、照片、账单 | ⌘O；生活记录中的导入及照片/账单入口 |
| AI 协作面板 | ⌘⌥I；标题栏图标 |
| 深入聊聊独立窗口 | ⌘⇧F，延续当前选中的对话 |
| 独立阅读 / 大画布 | ⌘↩；标题栏图标 |
| 偏好设置 | ⌘, |
| 切换知识库 | ⌘1–⌘9；侧边栏空间切换器 |
| 返回 / 前进 | ⌘[ / ⌘] |

主窗口关闭后，macOS 应用与菜单栏随手记继续可用。通过菜单退出会终止本地服务。编辑仍保留原有双击、自动保存、并发检查；独立阅读窗口只读。原有 URL 保持可用，搜索结果页也保留为旧链接入口。

| 设置 | 通用 / AI 助手 / 知识库 / 高级；AI 设置仍使用原有全局持久化接口 |

语音识别需用户主动开始并授权麦克风及系统语音识别；设备支持时优先本机识别，否则由系统决定服务可用性。AI 整理通过已配置的 Agent 运行只读任务，不直接写原始记录或 Wiki。真实麦克风输入、AI 外部服务、通知展示和 iPhone 硬件不能由匿名自动验收替代。

## 验证

```sh
pnpm typecheck
pnpm test
pnpm build
pnpm desktop:verify
```

桌面验收复制匿名 demo 到临时工作区，覆盖 12 个栏目、原生菜单、搜索、Inspector、设置、语音确认、随手记保存、跨库拒写、独立阅读、深聊、照片入口和本地会话隔离。关闭后删除测试工作区；截图仅来自匿名数据，放在被忽略的 `.impeccable/reviews/`。

验证已打包应用：设置 `TWH_DESKTOP_EXECUTABLE` 为 `.app/Contents/MacOS/The Way Here`，再运行 `pnpm desktop:verify`。

## 连接已有资料目录

生活记录 → 原目录连接 →「连接原始目录」。桌面端直接选择 Finder 中的文件夹；Web 端填写本地服务所在电脑上的绝对路径。浏览器上传不提供可持续读取的本机路径，因此上传文件仍明确标为「一次性导入副本」。

- 普通目录中的 Markdown / TXT 保留原处，包含子目录；正文不复制进工作区。单文件上限 2 MB、单目录最多 10000 份，隐藏文件和符号链接不收录。
- 新建知识库使用 `app/<id>/wiki` 保存生成的 Wiki，`app/<id>/sources` 保存随手记、照片/账单缓存、一次性导入与轻量来源引用。原有 `vault/<id>` 配置保持兼容，不自动搬移已有资料。
- 外部文件只读展示。在原来的编辑器中修改后，目录监听会刷新索引；按内容版本检测新增、修改和删除，同内容改名保留引用身份。
- 勾选「变化后自动更新 Wiki」后，后台将变更合并，使用已配置的 AI 按原有知识构建规则更新受影响页面。每批最多 50 份，与当前库任务互斥，始终绑定来源所属知识库。关闭后仍刷新原文，Wiki 保持待更新，点击「更新 Wiki」手动处理。
- 没有可用 AI、运行失败或目录暂不可用时保留待更新状态并显示原因。AI 失败不会无限自动重试；调整配置后点击「更新 Wiki」。运行期间再次修改的文件会进入下一次更新。
- 文件消失后保留不含正文的失效来源引用，供已有 Wiki 追溯与复核。断开连接只停止同步，保留原文件和 Wiki。删除整个知识库也只删除应用管理目录，不访问原目录。

自动化验收使用临时匿名原目录，覆盖零正文复制、外部编辑刷新、改名/删除、符号链接隔离、跨库任务、后台更新、离线/失败、重启和安全断开。真实 AI 生成质量仍取决于用户配置的模型与知识质量门。

## 全新安装验收

`node scripts/verify-first-install.mjs` 将实际安装包复制到临时 Applications 目录，用全新的用户数据目录启动，不提供工作区环境变量，并仅提供系统 PATH。覆盖自动创建、空库全部栏目、随包 Python 四项质量门、AI 设置直达、随手记，以及替换安装包后的配置、搜索和存储保留。`pnpm desktop:verify` 继续覆盖匿名已有知识空间的完整功能及目录连接、双链。

桌面端演示内容直接从 Web 端的 `vault/demo` 打包，不从 UX 设计稿生成故事或数据。保留 Wiki、原始记录、照片、账单及隐藏附件目录，继续使用 `vault/demo` 路径以维持已有资源引用。首次启动和旧版托管空间升级会注册缺失的 demo；个人库仍为默认，已有 demo 和个人内容不覆盖。
