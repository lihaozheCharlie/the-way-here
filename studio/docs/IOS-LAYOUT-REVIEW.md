## 本轮问题与修复

| 实际问题 | 原因与修复 | 验证方式 |
|---|---|---|
| 首页内容看起来放大、主操作难找 | 原稿常用 390 宽画布，NOW-1 特设 980 高；真实小屏只有 667 高。原生大标题、重复说明、较高输入区与固定操作区共同消耗首屏。收紧阅读层级，已有草稿／较矮窗口／大字号采用紧凑伴随说明，将说明放回可滚动内容。未全局缩放或关闭 Dynamic Type。 | 普通、XXXL、横屏及键盘场景分别验证输入与主操作边界。 |
| 保存／整理实际被导航栏覆盖，点击整理误进理解 | `TabView` 外层 `safeAreaInset` 没有可靠减少内部导航栈的可用区域。失败录屏显示操作位于自定义导航后，真实点击 `(342.45, 611.80)` 命中理解入口；通过旧“位于 App frame 内”检查也不能证明无遮挡。改为 `TabView` 与自定义底栏在真实 `VStack` 中分配空间，并隐藏系统重复标签栏。根因不是自适应操作布局算法。 | 加强完整按钮 frame 必须位于真实底栏上边界之前；真实点击整理进入确认，最终小屏全部通过。失败证据保留在 `.runtime/ios/layout-final-small-attachments/`。 |
| 首页控件标识被祖先覆盖 | NOW-1 标识限于主滚动内容，固定操作区独立；保留子控件标识与可访问性分组。 | 测试按真实保存标识定位并点击，未改用跳转或状态注入。 |
| 窄屏长操作文案、阅读页底部动作容易挤压 | 复用 `BottomActionBar` 与单控件树 `AdaptiveActions`，测量完整标签后横排／纵排；深页标题改内联、卡片与长标题允许自然换行；主要阅读操作固定在内容之外，末尾内容获得对应空间。 | 标准屏首轮离线查看 Understanding 卡片、结构页、长信滚动、人物页，未见新增裁切或操作遮挡；最终标准屏 71 项已通过；对应渲染观察见下表。 |
| 写作／聊天工具易被键盘覆盖，照片步骤操作难以发现 | 写作工具与聊天输入保留在键盘上方；照片步骤操作固定于底部；确认表单使用紧凑标题与固定主操作，内容可滚动。 | 最终小屏真实生产入口、键盘与照片两步骤用例通过。 |
| 布局调整后，旧测试仍选择背景控件或使用固定安全边界 | 纠正输入增加明确标签与唯一标识，表单标识与固定页脚分开；想法测试使用已有输入标签。Future 路径须真实滚到导航与保存页脚之间再点击；Recovery 使用实际导航／键盘边界代替固定减 140；导入控件标识与键盘路径同步修正。 | 首轮完整 69 项的失败保留为失败，不用历史通过覆盖；当前完整 71 项已通过，保留实际滚动、输入、保存及持久化断言。 |
| 照片候选第二行在页脚下仍被认为可点击 | 仅存在／hittable 不足以证明真实前台可点；检查候选完整 frame、确认选择时弹层仍在，并以 large 弹层提供内容空间。 | Fresh15 的单项失败触发本次修正；最新照片默认与显式排除两项实际 2/2 通过，未弱化保存结果断言。 |

标准屏首轮记录列表还发现自绘导航箭头与系统导航箭头重复。当前源码已由共享 `DocumentRow` 默认不绘制自定义箭头，保留系统导航指示；最终同轮记录列表截图已确认每条记录仅一枚导航箭头。

## 证据边界

- 原稿 HTML 的字号、间距、层级是设计依据，不照搬其 980 高静态页面，也不牺牲原生最小触控区域或大字号支持。
- 模拟器运行时中文仍存在缺字／方框；英文页也有动态中文资料及部分静态中文标签。因此可确认上述几何边界与真实交互，**不能宣布中英文全页视觉可读性验收完成**。翻译资源齐全不等于运行时每个标签均已翻译并可读。
- 本轮没有执行真实模型、读取私人资料、操作用户 iCloud 或新增真机系统验收。此前 [验收审查](IOS-UX-ACCEPTANCE-REVIEW.md) 的 P1–P4 系统与设备边界继续保留。
- 当前签名 IPA 已通过签名检查；实体 iPhone 当前不可用，尚未安装此次新包，不能把模拟器通过写成新包真机验收完成。
- 结果包 summary 仍记录若干 priority inversion、Modifying state during view update，以及一条 UIReparentingView 层级运行时告警；本轮未归因，不能声明运行无告警。
- 任何后续 App／测试源码变化需重新绑定源码摘要与适当验证；旧安装包、旧 digest 或历史全套结果不能替代新快照。
