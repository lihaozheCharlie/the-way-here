文件夹与文档小标题

两处交互的 UX 设计稿。核心原则:磁盘上有什么,界面上就是什么;阅读与编辑共用同一套小标题。

1打开文件夹

取消“日记 / 笔记”导入。唯一入口是“打开文件夹”,选中的文件夹直接作为目录树的顶层,往下按磁盘真实结构展开任意层级。点击任一文件夹,中栏列出它里面的文件。

2文档与小标题

文档里没有“阅读 / 编辑”按钮:打开就是阅读排版,双击正文直接编辑,按 Esc 完成。小标题是正文右侧的同一个组件,有三种状态:展开、收起、没有小标题。

做事的方法

##为什么要写下来

想法在脑子里总是显得很完整,一旦落到纸上才发现缺了好几块。写作不是记录结论,而是检验思考的过程。

当一个问题反复出现,最好的办法不是再想一遍,而是把它写成一段话,然后看看哪一句站不住脚。

##三个核心做法

下面的做法来自过去一年的反复试错,每一条都对应一个具体的失败经历。

###先定义完成的样子

开始之前先用一句话写下“做完是什么样”。没有这句话,任务永远可以再多做一点。

这句话也是之后复盘的基准:偏差在哪里,一眼就能看见。

###把大事拆到半天以内

超过半天的任务,几乎都会在中途被打断。拆小之后,每一块都有清晰的开始和结束。

拆分的标准不是工整,而是每一块完成后都能带来一次确认。

###每天留一次回看

睡前花十分钟看一眼今天写下的东西,删掉冗余,留下真正有用的一两句。

##常见的坑

最常见的问题是把整理当成工作本身。整理只是手段,真正的产出是后面被反复使用的判断。

另一个坑是追求一次写完。多数好文档都是被一点点改出来的。

##接下来怎么做

从下周开始,每个任务都先写一句完成标准,并在周末回看一次实际偏差。

如果一个月后这件事依然有效,再把它固化成固定流程。

目录
    • 展开:一条细线加一列标题,当前位置蓝色高亮,滚动自动跟随,点击平滑跳转;标题过长单行省略
    • 收起:只剩一列短横线(二级长、三级短),当前位置蓝色;鼠标移上去浮出完整目录,点浮层右上角箭头可固定展开
    • 没有小标题:不显示目录也不留占位,正文位置不变;写下第一个 ## 后目录自动出现
    • 编辑:标题前显示 ## 标记,目录高亮跟随光标所在段落;点目录条目,光标直接落到该标题
