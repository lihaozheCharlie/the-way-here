# 照片记忆冷启 · 当前流程

## 目标与界面范围

从几张照片开始，先看得见的线索，再由用户认人、讲述和纠正，最后将确认过的记忆收进已有理解。照片不是自动生成「人生事实」的依据。

本功能是现有生活记录流程的局部扩展，采用 Operate 模式，以用户照片为主要内容。沿用档案纸面、既有字体与颜色变量、细边界和克制操作，不另建媒体应用或全局设计系统。交付范围为 1280–1600px 桌面 Web；不包含移动端设计。

入口在「带一段记录进来」的第四类「照片」。照片采用「选照片 → 认人物 → 讲故事 → 确认讲述 → 收进理解」五段进度，一屏只承载当前阶段的主要任务。导入弹窗与其他类型统一采用「选类型 + 加材料 → 确认位置」两步及同样的类型卡片；第一步选照片，第二步命名并确认位置。人物影像复用既有关系列表、图谱和详情页，AI 对话继续进入共享上下文 Agent 抽屉。

## 使用流程

1. **选好照片。** 先添加、预览、移除照片，建议选择同一段旅程的一组照片；下一步为记忆命名并确认位置，默认存入「照片记忆」。每批 1–10 张 JPG、PNG 或 WebP，单张可选择最多 100 MB；超过 20 MB 时在本地后台逐张压缩为最长边 2560px 的 JPG，压缩后合计最多 100 MB；不接收动画或 HEIC，HEIC 请先导出为 JPG。导入保存原文件或大图的压缩副本，不改动电脑上的原文件，不自动调用模型。
2. **逐组认人物。** 浏览器后台逐张检测人脸，将各照片中的候选人物按相似特征组成“疑似同一人”队列，必须逐组核对，允许移出误分头像。确认一次保存整组；不确定的人脸单独显示。左侧缩略头像表示当前人物及确认状态，主体一次只编辑一人；完整照片与裁剪微调默认折叠。搜索框点击或聚焦即展开，支持姓名和别名搜索，列表分为「已有人物」与「使用称呼」，展开时不遮挡确认和跳过按钮。搜索过程保留已选人物，明确选择后才改变关联。同名时提示可以直接选择已有档案；选中后及确认按钮均区分关联已有档案与使用新称呼。确认后默认使用裁剪头像，并继续下一位；也可不记录某人，或保留候选并先讲故事。未命名候选不阻塞讲述确认；已选称呼或改动过的已有人物必须确认或选择不记录。没有人脸也能继续。
3. **逐条讲故事。** 先选择是否让 AI 看图；无论是否分析，每张照片统一问「这张照片给你留下了什么记忆？」，不针对画面细节生成问题。一次显示一张照片，用户可留下原话、跳过或改写整段故事。逐问回答先存在本机，以照片序号与名称、问题和回答分别标记后加入讲述，不调用 AI 自动总结。原始逐条回答保留在账目中；整段编辑后的文本以核对页为准。AI 候选线索折叠展示，并明确不是人生事实。需要 AI 继续对话时复用共享抽屉；若存在未确认的本机讲述，先引导核对确认。
4. **独立核对讲述。** 下一步进入默认只读的报告草稿，旁边保留「编辑」和返回讲述的动作；尚未提交的当前回答会先并入草稿。确认前可核对照片数与已指定人物，点击「确认这份讲述」后才保存为来源确认稿。
5. **收进理解。** 单独展示照片、头像人物与已确认讲述摘要，再由「构建这段记忆」启动写入。成功完成构建及质量门后发布人物影像关联，显示完成状态与人物图谱链接。之后继续对话产生新草稿，须重新确认再构建。

## 保存与隐私边界

- **本地分组不自动命名。** 浏览器使用随应用分发的 MediaPipe WASM 与 BlazeFace 模型，仅产生候选人脸框，不访问 CDN；每批照片共用一个后台线程和模型，逐张检测，整批完成或取消后释放，异常时重建线程继续剩余照片；多张照片使用本地 SFace 特征比对，仅建议同批次分组，不搜索历史人脸库或自动命名。特征模型异常时仍可逐人确认，原始特征不持久化或发送给模型。服务端使用 Sharp 从转正副本裁剪头像。
- **点击看图使用当前模型。** 无需额外勾选，点击看图后分析副本会发送给 AI 设置中当前选中的模型服务；原图不会作为分析附件。使用既有 Codex 或用户配置的模型路径，先检查视觉输入能力，不支持时明确提示，不自动切换供应商。外部服务如何处理数据仍取决于其政策。
- **对话也有发送边界。** 丰富故事时发送候选线索、用户指定的称呼和讲述上下文，不重新发送图片；不能把「图片本地检测」理解为「整个对话离线」。
- **草稿不是 Wiki。** 未确认的人物、讲述、逐条回答、跳过记录、当前步骤和输入中尚未提交的回答按知识库与照片批次暂存在本机浏览器。离开、刷新后自动加载，无需选择恢复或丢弃；未编辑的旧缓存不覆盖服务端最新讲述，不自动确认或构建。浏览器存储失败会提示，并在关闭窗口前警告。
- **来源可回看。** 工作区提供「保存原图」。模型线索与 AI 未确认稿保留在隐藏元数据中，本机讲述在确认前只留在浏览器；确认后的讲述才进入可摄取的来源报告；构建不改写原始照片。

## 人物影像与第一版限制

用户已选人物的页面 ID 在保存、对话和构建中完整保留。没有页面 ID 的称呼是待匹配项，不等于新人物；模型可按用户授权结合姓名、别名、档案和已确认讲述合并到已有页，“我”和“自己”按叙述者本人档案处理，无需二次询问。无法判定则保留未决并继续。模型返回人物关联后，服务端验证属于当前批次与知识库、未覆盖用户明确选择，质量门成功后才回存关联并发布影像。旧报告中的禁止同名合并占位文案由构建上下文明确纠正，历史来源不被改写。头像和照片证据进入关系列表、图谱及人物详情，照片可回到来源报告。移除人物标注后停止提供该关联头像。

删除普通来源报告后，相关影像不再出现在人物视图，但隐藏来源目录中的原图仍然保留。第一版没有整批照片管理或删除界面；删除报告不等于删除照片。当前也不支持视频、自动识人或自动关系推断。

## 验证记录

流程已通过类型检查、自动测试与生产构建。1280px 与 1600px 浏览器使用匿名 mock 验证主要流程，并检查构建请求参数、确认与构建时间驱动的成功态及图谱链接、修改后重新确认的门禁，以及 AI 分析失败后的重试请求。

本轮没有发起真实模型调用或写入知识库。图片附件、结构化输出、确认和构建链路由替身运行时测试覆盖，不代表已验证具体外部模型的视觉质量或数据处理政策。

实现边界与持久化协议参见 `ARCHITECTURE.md` 的「照片记忆冷启」一节。本简报记录该功能的局部选择；`DESIGN.md` 仅同步照片流程约定，不改动全局主题或其他材料流程。

### 生活记录页的入口

待完成的照片与账单记忆以缩略卡片展示，点击后在弹窗内继续整理。已构建的照片记忆不再占据顶部区域；下方列表的“打开照片记忆”始终可用，支持查看、修改人物与讲述、重新确认。关闭弹窗后，未确认编辑沿用本机草稿恢复机制。进入生活记录页仅恢复关联会话，不自动打开 Agent 对话。

顶部导航与右下角唯一的下一步入口共用跳转规则；检测中仍可讲故事，保存或构建时统一禁用。打开时自动加载本机草稿，再继续检测；不展示恢复提示或恢复／丢弃按钮。检测显示准备、定位、比对及照片序号；定位超时 30 秒，分组超时 15 秒。分组失败保留人脸框，本批后续照片跳过特征加载，仍可逐个确认。
