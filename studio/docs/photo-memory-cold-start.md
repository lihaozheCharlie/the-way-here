# 照片记忆 · 当前流程

## 目标与界面范围

照片记忆从一组照片开始，由用户确认人物并讲述故事，最后把确认过的内容收进已有理解。系统不会仅根据画面推断身份、关系、情绪或人生事实。

入口位于「带一段记录进来」的「照片」。导入仍分为选择照片、命名并确认位置两步；导入后的标注弹窗只保留「认人 / 讲故事」两步。人物影像复用关系列表、图谱和详情页，继续聊天复用共享 Agent 抽屉。

## 使用流程

1. **导入照片。** 每批可选择 1–10 张 JPG、PNG 或 WebP。浏览器允许选择单张不超过 100 MB 的照片；超过 20 MB 时在本地后台压缩为最长边 2560px 的 JPG，压缩后合计最多 100 MB。不接收动画或 HEIC。系统保存原文件或大图的压缩副本，不改动电脑上的原文件。
2. **认人。** 浏览器在本地逐张检测人脸，并沿长图的长边分块复检。同批照片中的相似人脸会组成候选组。点击人物框只进入范围调整，可以拖动框改变位置、拖四角改变宽高，也可以拖上边或下边中部单独调整高度；点击框上的姓名标签后，人物填写卡才会在框附近浮出。浮卡不改变照片和页面布局，点击人物框与浮卡之外的位置会完整关闭。选择人物或填写称呼后，同组照片同步更新。用户也可以点击「圈选漏掉的人」直接在照片上画新框。误分的人脸可移出组后单独标注；「不记录这个人」只删除当前照片中的这次标注。未命名候选不会阻塞下一步，没有检测到人脸也可以继续。
3. **讲故事。** 胶片条切换当前照片，每张照片有独立故事。已填写和未填写照片使用不同文案与状态圆点；空故事可点击「AI 帮你写」，系统只把当前照片预览发送给当前模型并将结果填回这一张，用户仍可修改。允许部分照片留白，但整批至少需要一段讲述。
4. **收进理解。** 点击「收进理解」后，系统按照片顺序组合故事，保存本次确认内容并直接启动构建与质量门。人物仍有未保存修改时不能构建。完成后显示人物图谱入口；修改人物或故事后可以再次构建。

## 保存与隐私边界

- **本地检测不命名。** MediaPipe BlazeFace full-range、SFace 和相应运行时随应用本地提供，不访问 CDN。人脸特征只存在于当前批次的浏览器内存中；本机草稿只保存候选组成员 ID，不保存特征，也不搜索历史人脸库。
- **AI 起草按单张发送。** 只有用户点击「AI 帮你写」时，当前照片的 JPEG 预览才会发送给当前模型。原图不会作为附件；不支持图片输入的模型会直接提示。外部服务如何处理数据取决于该服务的政策。
- **继续聊天不发送图片。** 照片记忆的共享对话只带入人物与讲述上下文，并把结果保存为待确认草稿。
- **本机草稿不是 Wiki。** 未确认的人物、逐照片故事、当前步骤和候选分组按知识库与照片批次保存在浏览器中，刷新后自动恢复。旧五步流程留下的逐问回答仍可迁移到当前逐照片故事；该兼容逻辑只用于读旧草稿，不再暴露旧流程入口。
- **确认后才可摄取。** 未确认的 AI 草稿不会写入可摄取报告。点击「收进理解」后，故事和用户指定的人物才进入来源报告并启动构建。构建不改写原始照片。

## 人物影像与删除

用户明确选择的人物页面 ID 会贯穿保存、对话和构建。只有称呼而没有页面 ID 时，构建可结合本库姓名、别名和已确认讲述匹配已有档案；不能判定时保持未决，不根据外貌识人。质量门成功后才发布人物影像关联。

删除普通来源报告后，相关照片记忆会立即从待完成区域、待构建计数和当前打开状态中移除，人物视图也不再展示对应影像。隐藏来源目录中的原图仍独立保留；当前版本没有整批照片文件管理或删除界面。
