# 桌面端 UX 重构设计稿

> 范围：`studio/apps/web` 桌面端（`desktop.css` + 各页面），覆盖 DESKTOP.md 列出的全部栏目。
> 方法：本稿基于对现有组件（`markdown.tsx`、`Sources.tsx` 等）与样式表（`archive-theme.css`、`base.css`、`sources-redesign.css`、`refinements.css`、`desktop.css`）的逐项审查得出，未依赖实时截图（当前沙箱环境无法对本项目的自定义端口开启预览代理）。所有问题点均标注了代码依据，方便对照验收。

---

## 1. 现状诊断

### 1.1 核心投诉点（用户明确指出）

**A. Markdown 阅读/编辑器**（`shared/markdown.tsx` + `archive-foundation.css`）

- 顶部身份条（文件夹路径 + 文件名输入框 + 保存状态 + 操作按钮）挤在一条 58px 高的横条里，四类信息（路径、文件名、同步状态、按钮）视觉权重几乎相同，用户看不出"文件名"才是这页唯一该被关注的标题。
- 正文与"属性面板"（`note-properties`，即 frontmatter 的 tags/aliases/date 等）永远置顶铺满一整块，用胶囊 chip（`.note-property-token`）平铺展示，哪怕只有一个 tag 也占一整行网格，视觉噪音大、和正文抢注意力。
- 右侧 `document-outline`（本页目录）用 220px 定宽列常驻显示，多数短文档目录只有 1-2 级却依然占屏，且没有"合上/收起"的入口。
- 双击进入编辑、`textarea` 等高字体（`ui-monospace`）与预览态的正文字体（衬线 `--font-display`）切换突然，编辑时"渲染感"完全消失，来回横跳。
- 保存状态用一段文字 + 小圆点（`document-save-state`）挂在右上角，字号 10px，容易被忽略，也没有"刚刚保存成功"的短暂确认反馈。

**B. 生活记录三栏浏览器**（`Sources.tsx` + `sources-redesign.css`）

- 三栏结构：文件夹（220-310px）｜文件列表（220px 起）｜预览区，属于合理的 macOS Mail/Finder 范式，但当前实现把"信息密度"和"呼吸感"都压到了下限：
  - 文件条目标题 12px、摘要 10.5px、表头计数 10px（`source-file-select > b/small`），比 iOS/macOS 系统列表常用的 13-15px 明显小，长时间阅读吃力。
  - 每个文件条目自带描边 + 命中态叠加阴影（`.source-file-row.active { box-shadow: 0 8px 20px … }`），列表滚动时大量卡片阴影叠加，视觉"发闷"。
  - 折叠态列宽固定 54px 图标条，与展开态之间用 grid-template-columns 生硬切换，没有过渡动画，体感是"跳"而不是"收起"。
  - 顶部还叠着筛选按钮组、搜索框、批量构建横幅、月份筛选条四段独立工具区，每段各有独立留白节奏，纵向堆叠后首屏经常看不到文件列表本身。

**C. 整体桌面交互舒适度**

- 全局强调色 `--accent-primary: #578a83`（灰绿）与警示色 `--accent-attention: #b9874c`（棕金）搭配还算克制，但组件级别各自为战：卡片阴影、描边色、圆角在 `archive-foundation.css / archive-theme.css / refinements.css / desktop.css` 四个文件里反复覆盖同一批选择器，同一控件在不同页面圆角从 5px 到 22px 都出现过，缺一套统一的"桌面级" token。
- 桌面窗口内没有真正意义上的原生分栏毛玻璃、无边框融合标题栏的处理（`desktop.css` 只是把 Web 版网格做了折叠，没有针对"窗口感"单独设计）。

### 1.2 页面清单速览（按 DESKTOP.md 栏目）

| 栏目 | 现状问题（基于共享样式表推断） |
|---|---|
| 此刻 / Today | 卡片信息优先级不清晰，提醒、话题计数、最近线索平铺 |
| 值得聊聊 / 聚焦工作区 | 对话与证据面板密度高，与 Reader 右侧面板同款问题 |
| 生活记录 / Sources | 见 1.1-B |
| 照片记忆 / 账单记忆 | 弹层内多步骤堆叠，确认/跳过按钮层级不突出 |
| 已有理解总览 / 理解自己 | 大量小卡片 + tag 胶囊堆叠，同 note-properties 的密度问题 |
| 近况回信 / Letters | 版本/来源/推理视角标签拥挤 |
| 人与世界 / Relationships | 关系图与列表切换时布局跳动 |
| Reader | 见 1.1-A |
| 协作与任务 / Inspector | 信息层级深，任务历史/审批/差异挤在同一窄栏 |
| 设置 / Preferences | 表单密度尚可，但与其余页面视觉语言不统一 |

## 2. 设计原则（本次重构的判定标准）

借鉴 macOS / Apple HIG 的桌面软件质感，但不复制 Apple 的具体皮肤，落成"The Way Here"自己的桌面语言：

1. **一屏一主角**：任何界面只保留一个视觉焦点（正文 / 文件列表 / 关系图），其余都是可收起的辅助面板，默认收起或极简展示。
2. **信息分层用留白和字重，不用更多颜色**：延续现有灰绿+暖金双色体系，但压缩到"背景 / 内容 / 强调"三级对比，弱化装饰性描边和阴影。
3. **控件要"够大够稳"**：桌面鼠标精度高，但长期使用的列表、按钮字号不应低于 13px；点击目标不小于 28×28px。
4. **状态反馈要"轻but确定"**：保存、同步、失败要有清晰但不打扰的反馈（例如短暂高亮 + 文案渐隐），不用常驻小圆点。
5. **面板可收放，且收放要有动效**：折叠栏、右侧目录、属性面板统一用 200ms 的宽度/透明度过渡，不允许"瞬间消失/出现"。
6. **一致的圆角、阴影、分割线体系**：全局只保留 2 级圆角（8px 常规控件 / 14px 卡片容器）、1 套阴影 token、分割线只用 `--line`，不再逐文件覆盖。

## 3. 设计系统升级

### 3.1 色板（在现有基调上收敛，非推翻重来）

| Token | 现状 | 建议 | 说明 |
|---|---|---|---|
| `--paper` | `#fbfcfc` | `#fbfbfa` | 更贴近纸感的暖白，减少屏幕"冷白"疲劳 |
| `--canvas` | `#f4f7f6` | `#f2f3f1` | 窗口底色，与 paper 拉开约 4% 明度差，形成"纸放在桌面上"的层次 |
| `--ink` | `#263440` | 保留 | 主文字色，对比度已足够 |
| `--muted` / `--faint` | 两个近似灰绿 | 合并为一个 `--muted`，去掉 `--faint` 的冗余定义 | 现有两个变量语义重叠，造成小字号大小写不一 |
| `--line` | `#d9e1df` | `#e3e6e4`（更浅） | 分割线进一步弱化，靠留白分区，不靠描边 |
| `--accent-primary` | `#578a83` | 保留 | 品牌绿，用于唤起、激活态、链接 |
| `--accent-attention` | `#b9874c` | 保留，但只用于"待处理/需要你" | 避免被当成普通强调色滥用 |
| 新增 `--radius-control` | — | `8px` | 按钮、输入框、chip 统一 |
| 新增 `--radius-panel` | — | `14px` | 卡片、面板、弹层统一 |
| 新增 `--shadow-panel` | — | `0 8px 24px rgba(38,52,64,.06)` | 唯一的浮层阴影，弃用逐页自定义阴影 |

### 3.2 字体节律

- 正文（阅读态）：保留 `--font-display`（衬线），字号 16px / 行高 1.85，取消预览态和阅读态的字号差异（现状 preview 14px、reader 未显式设置，导致两态视觉体重不一致）。
- 界面文案：`--font-ui`，桌面端最小字号从 10px 提升到 **12px**（次要信息如时间戳、计数）、**13px**（列表主要文字）、**15px**（页面/面板标题）。彻底移除现有 10px / 10.5px 用法。
- 等宽字体仅用于编辑态正文和快捷键 `<kbd>`，编辑态字号从 13px 提升到 **15px**，行高 1.8，缩小与阅读态的"体感落差"。

### 3.3 间距与栅格

- 统一 8px 基础栅格：控件内边距 8/12/16，面板内边距 20/24，页面外边距保持现有 `clamp` 逻辑不变。
- 三栏浏览器（Sources）列宽收敛为固定 **240px（文件夹）/ 280px（文件列表）/ 剩余空间（预览）**，去掉现状 220-310px 的不规则区间，折叠时统一收到 **48px** 图标条，并加 200ms 宽度过渡。

## 4. 全局框架重构

### 4.1 标题栏 + 侧边栏

- 标题栏与 macOS 原生无边框融合：标题栏底色与侧边栏底色统一为 `--canvas`，去除现状标题栏/侧边栏之间的硬分割线，只保留 1px 极浅描边。
- 侧边栏空间切换器、全局搜索框统一控件高度为 32px，圆角 `--radius-control`，避免现状 28px/36px 混用。
- 顶部本地导航（二级栏目 tab）下划线动效改为"背景块滑动"而非纯下划线，降低视觉跳动感（当前 `.section-tabs a.active` 只有 2px 下划线，切换时容易被忽略）。

### 4.2 统一的"右侧辅助面板"组件

当前 `document-outline`、`evidence-panel`、`note-properties`、Inspector 面板各自实现了一套"侧栏卡片"，视觉规则不统一。建议抽出一个通用 `AuxPanel` 组件规范：

- 默认**收起为图标条**（56px），点击展开为 280px，展开/收起都有过渡动效。
- 面板标题统一用 13px / 600 字重 + 分类图标，不再用 `<h3>` 裸标题。
- 面板内列表项统一 13px 字号、32px 行高，去除现状 10-11px 的目录项字号。

## 5. 页面级重构方案

### 5.1 Markdown 阅读 / 编辑器（对应用户吐槽的"标题悬浮 + tag 堆叠"）

**身份条重排（`editable-document-identity`）**

- 拆成两行，第一行只放"文件名"（放大到 18px、字重 600，作为唯一视觉焦点），第二行放"文件夹路径 + 保存状态 + 操作按钮"，三者用 12px 次要字号、灰色，靠左对齐、右侧只留操作按钮。
- 文件名输入框在非编辑态显示为**纯文本**（去掉输入框描边和背景），只有聚焦/双击时才切换为可编辑态的描边输入框，避免"看起来像文字却是控件"的违和感。

**属性/标签区改为"折叠式徽标条"**

- 默认只显示 1 行标签摘要（例如：`类型 · 笔记` `3 个标签` `2024-05`），点击展开才铺开完整的 `NoteProperties` 网格。
- Tag 胶囊（`note-property-token`）颜色从灌满的浅灰改为"描边 + 文字色"的轻量版本，减少视觉重量；不同 kind（tags / date / list）用极细的图标色差区分，而不是背景色差异。

**右侧目录默认收起**

- `document-outline` 从常驻 220px 改为默认收起的图标条（对应 4.2 的 AuxPanel），只有目录层级 ≥ 3 或文档超过一定长度时才建议自动展开一次。

**编辑态与阅读态视觉统一**

- 编辑态 `textarea` 字体从等宽切换为与阅读态一致的衬线字体、字号提升到 15px，行高 1.8，让"双击进入编辑"更像 Word/备忘录的"就地编辑"而不是切到代码框。
- 保存反馈从常驻文字改为：输入停顿 800ms 后右上角出现一次 **200ms 淡入 + 1.2s 后淡出**的"已保存"轻提示，日常不打扰，出错时才保留常驻红色文案。

### 5.2 生活记录三栏浏览器（对应"左边两列文件夹和文件很难受"）

- **列宽与密度**：按 3.3 节固定列宽，文件条目标题字号提到 14px、摘要提到 12px，去除逐条 `box-shadow`，命中态只用 `background: var(--surface-tinted)` + 左侧 3px 强调色竖线（细而不重）。
- **顶部工具区合并**：类型筛选、搜索框合并为一行（筛选 chip 靠左、搜索框靠右），月份筛选条改为可收起的"次级筛选"（默认收起，点击"按月回望"展开为下拉日历式选择器），避免四段工具区常驻占用首屏。
- **折叠动效**：文件夹栏/文件列表栏收起时，用 width + opacity 的 200ms 过渡，而不是 grid 列宽跳变。
- **空状态与批量操作**：批量构建横幅从常驻横条改为列表顶部的一条可关闭提示，减少"横幅常驻"的压迫感。

### 5.3 其余页面（简要方向，细节可在阶段二输出专项稿）

- **此刻 / Today**：信息按"需要你现在做的事" → "近期动态" → "历史回顾"三级视觉权重重排，卡片圆角、阴影统一到 3.1 节 token。
- **理解自己 / 已有理解总览**：tag/属性堆叠问题与 Reader 共用同一套 `NoteProperties` 组件，5.1 节的折叠式徽标条改造会同步解决这批页面的密度问题。
- **人与世界 / Relationships**：关系图与列表视图切换时保留滚动位置和缩放状态，避免布局跳动。
- **协作与任务 / Inspector**：拆分为"当前任务"和"历史记录"两个可切换的选项卡，而不是纵向无限堆叠。
- **设置 / Preferences**：套用统一控件规范（3.2/3.3），与其它页面视觉语言对齐。

## 6. 交互细节规范

| 交互 | 现状问题 | 规范建议 |
|---|---|---|
| 按钮 hover | 部分按钮无过渡，颜色突变 | 统一 `transition: background .15s ease, color .15s ease` |
| 按钮 active/pressed | 无按下反馈 | 按下时 `transform: scale(.97)`，120ms |
| 输入框 focus | 描边 + 3px 阴影环，规则不一致（部分用 `--accent-primary` 14%，部分未处理） | 统一 `box-shadow: 0 0 0 3px rgba(87,138,131,.16)` |
| 折叠/展开面板 | 无过渡，瞬间消失 | 统一 200ms width/opacity ease-out |
| 保存/同步反馈 | 常驻小字 + 圆点 | 轻提示浮现 + 自动淡出（见 5.1） |
| 危险操作（删除） | 已有红色按钮 + 二次确认弹层，规范可保留 | 维持现状，仅统一圆角与阴影 token |
| 快捷键提示 | `<kbd>` 样式已存在但零散 | 统一在 AuxPanel/工具条右侧用同一 `<kbd>` 样式展示 |

## 7. 分阶段实施建议

1. **阶段一 · 设计系统 token 统一**：落地第 3 节的色板/字体/间距/圆角/阴影 token，替换四个样式表里重复覆盖的规则，做到"改一处，全局生效"。
2. **阶段二 · Reader / Markdown 编辑器重构**：身份条重排、标签折叠、右侧目录收起、编辑态字体统一、保存反馈轻量化——直接解决用户点名的问题。
3. **阶段三 · 生活记录三栏浏览器重构**：列宽/密度/命中态/工具区合并/折叠动效。
4. **阶段四 · 全局框架（标题栏/侧边栏/AuxPanel 组件化）**：把阶段二三里抽出的"折叠面板"模式收敛成可复用组件，铺到 Inspector、理解自己、人与世界等页面。
5. **阶段五 · 剩余页面逐一走查**：按第 1.2 节清单逐页应用新 token 和组件，重点检查 tag/属性堆叠、卡片密度、折叠动效是否统一。
